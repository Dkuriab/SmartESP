# SmartESP — правила проекта

Репозиторий содержит прошивку ESP32 (корень) и ядро домашнего ассистента на
Python (`core/`). Общие правила — ниже; правила частей — в разделах и в
`CLAUDE.md` соответствующих папок. Главная цель правил: код разбит на
независимые модули, каждый из которых можно прочитать и отревьюить отдельно.

## Структура

```
SmartEsp/
  firmware/
    SmartEsp/           ← папка скетча: в Arduino IDE открывается SmartEsp.ino
      SmartEsp.ino      ← только связка: setup()/loop() вызывают модули
      src/
        common/
          Types.h       ← общие типы для обмена между модулями (без логики)
        <module>/       ← один модуль = одна папка
          <Module>.h    ← публичный интерфейс
          <Module>.cpp  ← реализация
      secrets.example.h ← шаблон секретов (в git)
      secrets.h         ← настоящие секреты (НЕ в git)
  core/                 ← ядро: Python-сервер на Mac (uv-проект), см. core/CLAUDE.md
  connectors/           ← наши MCP-коннекторы, каждый — свой uv-проект
  ui/                   ← веб-интерфейс (TypeScript), свой CLAUDE.md
  app/                  ← Mac-обёртка (Swift), свой CLAUDE.md
  docs/                 ← дизайн-документы и планы
  tools/                ← вспомогательные программы для ноутбука (не прошивка)
  README.md             ← назначение, сборка, плата и библиотеки с версиями
  CLAUDE.md             ← этот файл
```

Прошивка лежит отдельно в `firmware/SmartEsp/`: Arduino IDE просматривает всю
папку скетча, и файлы ядра и интерфейса (`core/.venv`, `node_modules`) ей мешают.
Ограничения Arduino IDE:
- Главный файл должен называться как папка скетча: `SmartEsp.ino`.
- IDE компилирует только файлы в корне скетча и в подпапке `src/` (рекурсивно).
  Код в других папках собран не будет.
- В папку скетча не кладём ничего, кроме прошивки.

Пути `src/...` ниже — внутри `firmware/SmartEsp/`.

## Ядро (`core/`)

Правила ядра, команды и структура — в [`core/CLAUDE.md`](core/CLAUDE.md).
У `ui/` и `app/` будут свои `CLAUDE.md`.

## Прошивка

Прошивка для ESP32. Пишется в Arduino IDE с использованием готовых библиотек.

### Модули

- Модуль — папка `src/<module>/` с одним классом.
- `.h` содержит только публичный интерфейс. Каждая публичная функция
  прокомментирована: что делает, параметры, что возвращает.
- Всё внутреннее — в `.cpp` (`private`-члены, `static`-функции, анонимный
  namespace). Наружу не торчит ничего, кроме интерфейса.
- **Модуль не подключает заголовки других модулей.** Модули не знают друг о друге.
- Исключение — `src/common/Types.h`: общие перечисления и простые структуры,
  которыми модули обмениваются через `SmartEsp.ino`. Только типы: никаких
  функций, кода, переменных и подключений модулей.
- Пины, адреса, настройки модуль получает через `begin(...)` или конструктор,
  а не из глобальных переменных и не захардкоженными внутри.
- Типовой интерфейс: `begin(...)` — инициализация, `loop()` — вызывается из
  главного `loop()`, плюс функции чтения/записи данных.
- **Никаких блокирующих вызовов** (`delay()`, долгие `while`-ожидания).
  Тайминги — через `millis()`, чтобы модули не тормозили друг друга.
- Общие глобальные переменные между модулями запрещены.

### SmartEsp.ino

- Только связка: создаёт модули, вызывает их `begin()` в `setup()` и `loop()`
  в `loop()`, берёт данные из одного модуля и передаёт в другой.
- Никакой собственной логики. Если в `.ino` появляется логика — её место в модуле.
- Весь поток данных между модулями виден здесь, в одном месте.

### Зависимости

- В `README.md` записаны точные версии: ядро платы ESP32 (esp32 by Espressif)
  и каждая библиотека. Arduino IDE версии не фиксирует — без этого списка
  проект может перестать собираться на другой машине.
- Добавил или обновил библиотеку — обнови список в том же PR.

## Общие правила

### Секреты

- Пароли Wi-Fi, токены, ключи — только в `secrets.h`, который в `.gitignore`.
- В git лежит `secrets.example.h` с теми же именами и пустыми значениями.
  Новый секрет добавляется в оба файла.

### Оформление

- Имена в коде (классы, функции, переменные, файлы) — на английском.
- Комментарии — на русском.
- Регистр имён зависит от части: прошивка — классы `PascalCase`, функции и
  переменные `camelCase`, константы `UPPER_SNAKE_CASE`; ядро (Python) — см.
  `core/CLAUDE.md`.

### Git и ревью

- В `main` напрямую ничего не коммитится. Любое изменение — через ветку и PR.
  Ревьюит и мёржит владелец проекта.
- Имена веток: `feature/<что>`, `fix/<что>`, `docs/<что>`, `refactor/<что>`.
- Один PR — одна задача (обычно один модуль). PR должен читаться за один раз.
- Сообщения коммитов — на английском, один смысл на коммит.
- Описание PR — на русском:
  - **Что** сделано;
  - **Зачем**;
  - **Как проверить** — для прошивки чек-лист шагов на плате (автотестов под
    Arduino нет); для ядра — команды и тесты.
