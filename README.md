# SmartESP

Умная колонка на ESP32-S3: ждёт слово «Миранда», отправляет вопрос на сервер
с нейросетью по WebSocket и проигрывает ответ. Ответ можно перебить словом.

Устройство прошивки — `docs/superpowers/specs/2026-11-15-firmware-design.md`,
правила проекта — `CLAUDE.md`.

## Установка на новом Mac с нуля

Ядро работает только на Mac с Apple Silicon (M1 и новее): распознавание речи —
`mlx-whisper`. Прошивать плату можно с любой системы (разделы ниже).

1. Проект:
   ```bash
   git clone https://github.com/Dkuriab/SmartESP.git SmartEsp
   cd SmartEsp
   ```
   Скачать может любой; чтобы пушить — войдите своим аккаунтом GitHub или
   заведите на этом компьютере свой ключ доступа (чужой ключ не копируйте).
2. Программы (если нет Homebrew — сначала https://brew.sh):
   ```bash
   brew install uv
   brew install --cask ollama   # затем один раз открыть приложение Ollama
   ```
3. Модель для ответов (~13 ГБ):
   ```bash
   ollama pull gpt-oss:20b
   ```
   Обновляетесь с версии, где диспетчером была Gemma, — см. «Обновление с прежних версий» в
   [`core/README.md`](core/README.md).
4. Ядро (`uv sync` в первый раз долгий — ставится torch):
   ```bash
   uv python install 3.12
   (cd core && uv sync)
   ```
   Интерфейс (нужен Node.js):
   ```bash
   cd ui && npm ci && npm run build
   ```
5. Запуск:
   ```bash
   cd core && uv run python -m smartesp
   ```
   Первый старт долгий: скачиваются модель распознавания (~1,6 ГБ) и голос
   по умолчанию Silero (~145 МБ), создаётся
   `~/SmartEsp/config.yaml`. Готово, когда в журнале «Запускаю сервер на
   ws://0.0.0.0:8765/device». Если macOS спросит про входящие подключения —
   разрешить, иначе колонка не достучится.
   Или приложением в строке меню, которое запускает ядро само. Нужны `uv` и
   Swift-тулчейн swift.org (https://www.swift.org/install/macos/, `.pkg` ставится
   в `~/Library/Developer/Toolchains`) или Xcode: Swift из Command Line Tools
   не умеет собирать пакеты на этой macOS.
   ```bash
   cd app && ./build.sh --install
   ```
   Затем открыть SmartEsp из «Программ»; при запросе доступа к «Документам»
   нажать «Разрешить». Подробности — в `app/README.md`.
   Обновиться и переустановить всё начисто (приложение, ядро, интерфейс, коннекторы; данные в
   `~/SmartEsp` не трогаются) — одной командой:
   ```bash
   tools/reinstall.sh            # или tools/reinstall.sh --no-pull — без git pull
   ```
6. Проверка без платы (второе окно терминала, из корня проекта) — должны прийти
   `reply_start`, звук и `reply_end`:
   ```bash
   uv run --project core python tools/fake_device.py --wav core/tests/data/privet.wav
   ```
7. Плата: в `firmware/SmartEsp/` выполнить `cp secrets.example.h secrets.h`
   (файл не в git — на новом компьютере его нет), вписать Wi-Fi и `SERVER_HOST` = IP этого Mac
   (`ipconfig getifaddr en0`), собрать и прошить — см. «Сборка в Arduino IDE».

## Подключение

| Устройство | Пин | GPIO |
|---|---|---|
| Микрофон INMP441 (L/R → GND) | SCK / WS / SD | 5 / 4 / 9 |
| Усилитель MAX98357A | BCLK / LRC / DIN | 7 / 6 / 8 |

Модуль: ESP32-S3-WROOM **N16R8** (16 МБ флеша, 8 МБ PSRAM).

## Сборка в Arduino IDE

Скетч — `firmware/SmartEsp/SmartEsp.ino` (открывать его, а не корень репозитория:
в корне лежит ядро, и Arduino IDE на нём спотыкается).

Ядро: **esp32 by Espressif 3.3.12** (Boards Manager). В нём же — ESP-SR 2.5.3
(эхо- и шумоподавление, VAD) и TFLite Micro (esp-tflite-micro 1.4.0, esp-nn 1.3.2)
для слова пробуждения; отдельно их ставить не нужно. Микрофронтенд TFLite
(признаки звука) вендорен в `src/wake_word/microfrontend/` (Apache-2.0).

Библиотеки (Library Manager, точные версии):

| Библиотека | Автор | Версия |
|---|---|---|
| WebSockets | Markus Sattler | 2.7.2 |
| ArduinoJson | Benoit Blanchon | 7.4.3 |

Tools:

| Пункт | Значение |
|---|---|
| Board | ESP32S3 Dev Module |
| Flash Size | 16MB (128Mb) |
| Partition Scheme | ESP SR 16M (3MB APP/6MB SPIFFS/3.9MB MODEL) |
| PSRAM | OPI PSRAM |
| USB CDC On Boot | Enabled — если подключены к порту «USB», а не «UART» |

Перед первой сборкой скопируйте `firmware/SmartEsp/secrets.example.h` в
`firmware/SmartEsp/secrets.h` и заполните Wi-Fi и адрес сервера.

## Сборка из командной строки

```bash
tools/build.sh
```

Нужен `arduino-cli` с установленным ядром esp32 3.3.12. Библиотеки нужных
версий скрипт ставит сам.

## Как пользоваться

1. На ноутбуке запустите тестовый сервер (`tools/test_server/README.md`)
   или настоящий сервер с нейросетью.
2. В `firmware/SmartEsp/secrets.h` — Wi-Fi и IP ноутбука, прошейте плату.
3. Скажите **«Миранда»** → короткий сигнал → задайте вопрос.
   Конец вопроса — 0,5 с тишины. С тестовым сервером колонка повторит
   вопрос вашим же голосом.
4. Во время ответа снова скажите «Миранда» — ответ оборвётся, можно
   задать новый вопрос.

Звуки (мягкие колокольчики): восходящий двухнотный звон — слово услышано и
«слушаю» (когда колонка сама задала вопрос); тихая капля — думаю; нисходящий
звон — ошибка (нет связи с сервером или ответ не пришёл за 15 с); «динь-динь-дон» —
перед объявлением ядра. Подробнее — в разделе «Звуки и протокол v3».

## Слово пробуждения

Слово ищет модуль `wake_word` — движок [microWakeWord](https://github.com/kahrendt/microWakeWord)
(потоковая модель TFLite Micro) на звуке после эхо- и шумоподавления AFE; WakeNet
выключен. Модель — «Миранда» ([archer-developer/miranda-wakeword](https://github.com/archer-developer/miranda-wakeword)),
файлы и источник — `tools/models/miranda/`. Дизайн —
`docs/superpowers/specs/2026-11-19-wake-word-engine-design.md`.

- Порог — **0,9** (средняя вероятность за 5 вызовов модели, ~150 мс); у автора
  0,5 — на синтетике слишком много ложных. После срабатывания детектор молчит 1 с.
- Громкость слова (`level`, дБFS) — максимум громкости за последнюю секунду,
  уходит в ядро вместе с событием `wake`.
- В журнале платы при запуске: `wake_word: модель … арена … из … байт`; на каждое
  срабатывание — `wake_word: слово услышано, вероятность …`.
- Прошивка с моделью — 2 685 566 байт (85% раздела APP 3 МБ; без неё и TFLite
  Micro было 2 490 554).

**Как поменять модель** (например, на свою «Кузю», обученную microWakeWord):

1. Положите `<имя>.tflite` и манифест `<имя>.json` (формат microWakeWord:
   `wake_word`, `model`, `micro.probability_cutoff`, `sliding_window_size`,
   `tensor_arena_size`) в `tools/models/<имя>/`, рядом — `SOURCE.md`, откуда они.
2. Встройте модель (порог можно задать свой, иначе — из манифеста):
   ```bash
   python3 tools/embed_model.py tools/models/<имя>/<имя>.json \
       firmware/SmartEsp/src/wake_word/ModelData.cpp --cutoff 0.9
   ```
3. Если модель использует другие операции TFLite, обновите список в
   `WakeWord.cpp` (`addOps`): иначе плата напишет в Serial, что модель не
   разместилась. Список операций модели: LiteRT `Interpreter._get_ops_details()`.
4. Поправьте `tools/test_embed_model.py` (путь к модели, фразы) и прогоните его.

Тесты: `uv run --project core pytest tools/test_embed_model.py` проверяет
встраивание. Замер модели на синтетике (голоса silero/xenia, silero/aidar,
vosk/male_0: «Миранда.» — выше порога, обычная фраза — ниже) нужен
`pymicro-features` и `ai-edge-litert`, которых нет в ядре, поэтому штатный
запуск его пропускает. Запускайте замер вручную в отдельном venv при каждой смене
модели или обработки звука (признаки, квантование, окно):

```bash
python3.12 -m venv /tmp/mww && /tmp/mww/bin/pip install pymicro-features==2.0.2 ai-edge-litert pytest
/tmp/mww/bin/python -m pytest tools/test_embed_model.py -s
```

**Проверка на плате** (автотестов под Arduino нет):

- [ ] «Миранда» с 1 м — срабатывает (сигнал), в Serial `слово услышано`.
- [ ] «Миранда» с 3 м обычным голосом — срабатывает.
- [ ] Громко включённый ответ колонки (длинный ответ на полной громкости) не
      будит её сам по себе: нет лишних срабатываний во время ответа.
- [ ] «Миранда» во время ответа — ответ обрывается (перебивание).
- [ ] Час разговора или ТВ рядом — сколько ложных срабатываний (записать число;
      ориентир на синтетике — около 2% фраз).
- [ ] Громкость слова (`level`) в журнале ядра правдоподобна: тихо/с 3 м —
      ниже, громко/с 1 м — выше.
- [ ] В Serial при запуске нет `wake_word: …` с ошибкой, нет
      `wake_word: не успевает` и `voice_frontend: loop() не забирает звук слова`.
- [ ] AGC: с выключенным WakeNet режим `AFE_AGC_MODE_WAKENET` усиления не даёт.
      Посмотрите вывод `print_pipeline` при запуске (есть ли AGC) и не стал ли
      звук вопроса, дошедший до ядра, заметно тише (журнал ядра / звук хода).
      Если тише — следующий шаг: `agc_mode = AFE_AGC_MODE_WEBRTC` в `voice_frontend`.

## Звуки и протокол v3

Протокол v3 добавил команду ядра `listen` (колонка сама начала разговор: звук
«слушаю» и слушание без слова пробуждения) и ответ `busy` (колонка занята).
Объявление ядра (`announce`) колонка принимает только в покое и тогда сама играет
сигнал «внимание»; занятая колонка отвечает `busy` молча, а звук объявления,
пришедший до этого ответа, не играет. Звуки
— готовые образцы (PCM 16 кГц, 16 бит, моно) в `src/audio_out/SoundData.cpp`; их
синтезирует `tools/make_sounds.py`, уровень (пик не выше 0,5 шкалы) уже внутри,
`AudioOut` только умножает на громкость. Файл `SoundData.cpp` руками не правится.

**Как пересоздать звуки** (изменили ноты в `tools/make_sounds.py`):

```bash
uv run --project core python tools/make_sounds.py                 # пишет SoundData.cpp
uv run --project core python tools/make_sounds.py --wav-dir /tmp/sounds   # + WAV для прослушивания
uv run --project core pytest tools/test_make_sounds.py            # длина, края без щелчков, пик
```

**Проверка на плате:**

- [ ] Слово «Миранда» → новый мягкий звон (восходящий, два тона), без щелчков.
- [ ] «Миранда, спроси меня что-нибудь» → колонка задаёт вопрос → звук
      «слушаю» → ответ принимается без слова пробуждения.
- [ ] Тишина 5 с после вопроса колонки → молча возвращается в ожидание.
- [ ] Запоздавший ответ большой модели (сложный вопрос, «…долго думает») → через
      время звон «внимание» и ответ целиком, с самого начала, без обрезанного
      первого слова.
- [ ] Объявление, пока говорите с колонкой (сложный вопрос, затем сразу
      «Миранда, …» и ещё вопрос) → разговор не прерывается звоном «внимание»,
      объявление звучит после.
- [ ] Ошибка (отключить сервер) → нисходящий звон; «думаю» — тихая капля.
- [ ] Громкость меняет и звуки, не только голос ответа.
- [ ] В журнале ядра колонка пишет `fw 0.3.0` (подтверждает, что залита новая прошивка).

## Ход ответа: событие `played`

Пока колонка говорит ответ, она раз в ~0,5 с шлёт ядру
`{"type":"played","turn":N,"bytes":B}` — сколько байт PCM ответа этого хода уже
отдано динамику (16 кГц, 16 бит, моно: 32000 байт в секунду), и последнее
`played` — прямо перед `playback_done`. По нему ядро знает, где сейчас речь
(мягкие прерывания на границе предложений). Это расширение протокола 3: номер
протокола тот же, старое ядро неизвестный `type` пропускает. При перебивании,
отмене хода и `stop_playback` итогового `played` нет.

**Проверка на плате** (тестовый сервер `tools/test_server` печатает все события):

- [ ] При запуске в Serial `SmartESP 0.4.0`.
- [ ] Вопрос → во время ответа в выводе сервера `played` примерно дважды в
      секунду, `bytes` растёт примерно на 16000 за раз, `turn` — номер хода.
- [ ] Перед `playback_done` — `played`, у которого `bytes` равен длине ответа:
      «ответ на ход N: X с» × 32000 (сервер шлёт кусками по 4096 байт — ровно).
- [ ] `python3 server.py --long` (очередь переполняется) → итоговый `bytes`
      меньше отправленного: считается только доигранное.
- [ ] «Миранда» во время ответа → `barge_in`, новых `played` старого хода нет.
- [ ] Вне ответа (покой, слушание вопроса, ожидание ответа) `played` не приходит.
- [ ] Обычное ядро (`core/`) с новой прошивкой работает как раньше: ответы,
      перебивание, объявления.

## Ядро на Mac

Настоящий сервер — ядро в папке `core/` (Python): распознаёт речь, отвечает
локальной моделью через Ollama и озвучивает ответ. Установка, настройка колонок
и запуск — в [`core/README.md`](core/README.md). Без платы ядро проверяется
поддельной колонкой `tools/fake_device.py`: вопрос из WAV, ответ — в WAV.
