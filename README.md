# SmartESP

Умная колонка на ESP32-S3: ждёт слово «Миранда», отправляет вопрос на сервер
с нейросетью по WebSocket и проигрывает ответ. Ответ можно перебить словом.

Устройство прошивки — `docs/superpowers/specs/2026-11-15-firmware-design.md`,
правила проекта — `CLAUDE.md`.

## Установка на новом Mac с нуля

Ядро работает только на Mac с Apple Silicon (M1 и новее): распознавание речи —
`mlx-whisper`. Прошивать плату можно с любой системы (разделы ниже).

1. Проект:
   ```bash
   git clone https://github.com/Dkuriab/SmartESP.git SmartEsp
   cd SmartEsp
   ```
   Скачать может любой; чтобы пушить — войдите своим аккаунтом GitHub или
   заведите на этом компьютере свой ключ доступа (чужой ключ не копируйте).
2. Программы (если нет Homebrew — сначала https://brew.sh):
   ```bash
   brew install uv
   brew install --cask ollama   # затем один раз открыть приложение Ollama
   ```
3. Модель для ответов (~13 ГБ):
   ```bash
   ollama pull gpt-oss:20b
   ```
   Обновляетесь с версии, где диспетчером была Gemma, — см. «Обновление с прежних версий» в
   [`core/README.md`](core/README.md).
4. Ядро (`uv sync` в первый раз долгий — ставится torch):
   ```bash
   uv python install 3.12
   (cd core && uv sync)
   ```
   Интерфейс (нужен Node.js):
   ```bash
   cd ui && npm ci && npm run build
   ```
5. Запуск:
   ```bash
   cd core && uv run python -m smartesp
   ```
   Первый старт долгий: скачиваются модель распознавания (~1,6 ГБ) и голос
   по умолчанию Silero (~145 МБ), создаётся
   `~/SmartEsp/config.yaml`. Готово, когда в журнале «Запускаю сервер на
   ws://0.0.0.0:8765/device». Если macOS спросит про входящие подключения —
   разрешить, иначе колонка не достучится.
   Или приложением в строке меню, которое запускает ядро само. Нужны `uv` и
   Swift-тулчейн swift.org (https://www.swift.org/install/macos/, `.pkg` ставится
   в `~/Library/Developer/Toolchains`) или Xcode: Swift из Command Line Tools
   не умеет собирать пакеты на этой macOS.
   ```bash
   cd app && ./build.sh --install
   ```
   Затем открыть SmartEsp из «Программ»; при запросе доступа к «Документам»
   нажать «Разрешить». Подробности — в `app/README.md`.
   Обновиться и переустановить всё начисто (приложение, ядро, интерфейс, коннекторы; данные в
   `~/SmartEsp` не трогаются) — одной командой:
   ```bash
   tools/reinstall.sh            # или tools/reinstall.sh --no-pull — без git pull
   ```
6. Проверка без платы (второе окно терминала, из корня проекта) — должны прийти
   `reply_start`, звук и `reply_end`:
   ```bash
   uv run --project core python tools/fake_device.py --wav core/tests/data/privet.wav
   ```
7. Плата: собрать и прошить — см. «Сборка в Arduino IDE». В прошивке ничего не вписывается:
   Wi-Fi колонке задают с телефона, ядро на Mac она находит сама — см. «Сеть: Wi-Fi с телефона
   и поиск ядра».

## Подключение

| Устройство | Пин | GPIO |
|---|---|---|
| Микрофон INMP441 (L/R → GND) | SCK / WS / SD | 5 / 4 / 9 |
| Усилитель MAX98357A | BCLK / LRC / DIN | 7 / 6 / 8 |

Модуль: ESP32-S3-WROOM **N16R8** (16 МБ флеша, 8 МБ PSRAM).

## Сборка в Arduino IDE

Скетч — `firmware/SmartEsp/SmartEsp.ino` (открывать его, а не корень репозитория:
в корне лежит ядро, и Arduino IDE на нём спотыкается).

Ядро: **esp32 by Espressif 3.3.12** (Boards Manager). В нём же — ESP-SR 2.5.3
(эхо- и шумоподавление, VAD) и TFLite Micro (esp-tflite-micro 1.4.0, esp-nn 1.3.2)
для слова пробуждения; отдельно их ставить не нужно. Микрофронтенд TFLite
(признаки звука) вендорен в `src/wake_word/microfrontend/` (Apache-2.0).

Библиотеки (Library Manager, точные версии):

| Библиотека | Автор | Версия |
|---|---|---|
| WebSockets | Markus Sattler | 2.7.2 |
| ArduinoJson | Benoit Blanchon | 7.4.3 |

Tools:

| Пункт | Значение |
|---|---|
| Board | ESP32S3 Dev Module |
| Flash Size | 16MB (128Mb) |
| Partition Scheme | ESP SR 16M (3MB APP/6MB SPIFFS/3.9MB MODEL) |
| PSRAM | OPI PSRAM |
| USB CDC On Boot | Enabled — если подключены к порту «USB», а не «UART» |

Схему «ESP SR 16M» выбираем ради моделей ESP-SR: Arduino прошивает их в раздел
`model` (адрес 0xC10000). Саму разметку подменяет `firmware/SmartEsp/partitions.csv`
(с прошивки 0.7.0): две копии прошивки по 4 МБ, LittleFS 4 МБ, модели — на том же
адресе. Arduino IDE по-прежнему считает пределом 3 МБ: когда образ перерастёт 3 МБ,
собирайте `tools/build.sh` (он поднимает предел до 4 МБ).

Таблица разделов меняется **только прошивкой по USB** — по воздуху её не поменять.
Колонка со старой разметкой (до 0.7.0) работает и с новой прошивкой, но образ больше
3 МБ по воздуху не примет («не помещается»). После первой прошивки по USB с новой
разметкой LittleFS форматируется заново: свои звуки ядро вернёт само при подключении,
обученную модель слова нужно отправить ещё раз (вкладка «Обучение» → прогон → «На колонку»).

Точка настройки Wi-Fi, поиск ядра и настройки во флеше используют библиотеки из самого ядра
esp32 (DNSServer, WebServer, ESPmDNS, Preferences) — ставить их не нужно.

## Сборка из командной строки

```bash
tools/build.sh
```

Нужен `arduino-cli` с установленным ядром esp32 3.3.12. Библиотеки нужных

## Как пользоваться

1. На ноутбуке запустите тестовый сервер (`tools/test_server/README.md`)
   или настоящий сервер с нейросетью.
2. Прошейте плату и задайте ей Wi-Fi с телефона (точка `Kuzya-xxxx`, см. «Сеть: Wi-Fi с
   телефона и поиск ядра»); ядро колонка найдёт сама.
3. Скажите **«Миранда»** → короткий сигнал → задайте вопрос.
   Конец вопроса — 0,5 с тишины. С тестовым сервером колонка повторит
   вопрос вашим же голосом.
4. Во время ответа снова скажите «Миранда» — ответ оборвётся, можно
   задать новый вопрос.

Звуки (мягкие колокольчики): восходящий двухнотный звон — слово услышано и
«слушаю» (когда колонка сама задала вопрос); тихая капля — думаю; нисходящий
звон — ошибка (нет связи с сервером или ответ не пришёл за 15 с); «динь-динь-дон» —
перед объявлением ядра. Подробнее — в разделе «Звуки и протокол v3».

## Слово пробуждения

Слово ищет модуль `wake_word` — движок [microWakeWord](https://github.com/kahrendt/microWakeWord)
(потоковая модель TFLite Micro) на звуке после эхо- и шумоподавления AFE; WakeNet
выключен. Модель — «Миранда» ([archer-developer/miranda-wakeword](https://github.com/archer-developer/miranda-wakeword)),
файлы и источник — `tools/models/miranda/`. Дизайн —
`docs/superpowers/specs/2026-11-19-wake-word-engine-design.md`.

- Порог — **0,9** (средняя вероятность за 5 вызовов модели, ~150 мс); у автора
  0,5 — на синтетике слишком много ложных. После срабатывания детектор молчит 1 с.
- Громкость слова (`level`, дБFS) — максимум громкости за последнюю секунду,
  уходит в ядро вместе с событием `wake`.
- В журнале платы при запуске: `wake_word: модель … арена … из … байт`; на каждое
  срабатывание — `wake_word: слово услышано, вероятность …`.
- Прошивка с моделью — 2 685 566 байт (85% раздела APP 3 МБ; без неё и TFLite
  Micro было 2 490 554).

**Как поменять модель** (например, на свою «Кузю», обученную microWakeWord):

1. Положите `<имя>.tflite` и манифест `<имя>.json` (формат microWakeWord:
   `wake_word`, `model`, `micro.probability_cutoff`, `sliding_window_size`,
   `tensor_arena_size`) в `tools/models/<имя>/`, рядом — `SOURCE.md`, откуда они.
2. Встройте модель (порог можно задать свой, иначе — из манифеста):
   ```bash
   python3 tools/embed_model.py tools/models/<имя>/<имя>.json \
       firmware/SmartEsp/src/wake_word/ModelData.cpp --cutoff 0.9
   ```
3. Если модель использует другие операции TFLite, обновите список в
   `WakeWord.cpp` (`addOps`): иначе плата напишет в Serial, что модель не
   разместилась. Список операций модели: LiteRT `Interpreter._get_ops_details()`.
4. Поправьте `tools/test_embed_model.py` (путь к модели, фразы) и прогоните его.

Тесты: `uv run --project core pytest tools/test_embed_model.py` проверяет
встраивание. Замер модели на синтетике (голоса silero/xenia, silero/aidar,
vosk/male_0: «Миранда.» — выше порога, обычная фраза — ниже) нужен
`pymicro-features` и `ai-edge-litert`, которых нет в ядре, поэтому штатный
запуск его пропускает. Запускайте замер вручную в отдельном venv при каждой смене
модели или обработки звука (признаки, квантование, окно):

```bash
python3.12 -m venv /tmp/mww && /tmp/mww/bin/pip install pymicro-features==2.0.2 ai-edge-litert pytest
/tmp/mww/bin/python -m pytest tools/test_embed_model.py -s
```

**Проверка на плате** (автотестов под Arduino нет):

- [ ] «Миранда» с 1 м — срабатывает (сигнал), в Serial `слово услышано`.
- [ ] «Миранда» с 3 м обычным голосом — срабатывает.
- [ ] Громко включённый ответ колонки (длинный ответ на полной громкости) не
      будит её сам по себе: нет лишних срабатываний во время ответа.
- [ ] «Миранда» во время ответа — ответ обрывается (перебивание).
- [ ] Час разговора или ТВ рядом — сколько ложных срабатываний (записать число;
      ориентир на синтетике — около 2% фраз).
- [ ] Громкость слова (`level`) в журнале ядра правдоподобна: тихо/с 3 м —
      ниже, громко/с 1 м — выше.
- [ ] В Serial при запуске нет `wake_word: …` с ошибкой, нет
      `wake_word: не успевает` и `voice_frontend: loop() не забирает звук слова`.
- [ ] AGC: с выключенным WakeNet режим `AFE_AGC_MODE_WAKENET` усиления не даёт.
      Посмотрите вывод `print_pipeline` при запуске (есть ли AGC) и не стал ли
      звук вопроса, дошедший до ядра, заметно тише (журнал ядра / звук хода).
      Если тише — следующий шаг: `agc_mode = AFE_AGC_MODE_WEBRTC` в `voice_frontend`.

## Звуки и протокол v3

Протокол v3 добавил команду ядра `listen` (колонка сама начала разговор: звук
«слушаю» и слушание без слова пробуждения) и ответ `busy` (колонка занята).
Объявление ядра (`announce`) колонка принимает только в покое и тогда сама играет
сигнал «внимание»; занятая колонка отвечает `busy` молча, а звук объявления,
пришедший до этого ответа, не играет. Звуки
— готовые образцы (PCM 16 кГц, 16 бит, моно) в `src/audio_out/SoundData.cpp`; их
синтезирует `tools/make_sounds.py`, уровень (пик не выше 0,5 шкалы) уже внутри,
`AudioOut` только умножает на громкость. Файл `SoundData.cpp` руками не правится.

**Как пересоздать звуки** (изменили ноты в `tools/make_sounds.py`):

```bash
uv run --project core python tools/make_sounds.py                 # пишет SoundData.cpp
uv run --project core python tools/make_sounds.py --wav-dir /tmp/sounds   # + WAV для прослушивания
uv run --project core pytest tools/test_make_sounds.py            # длина, края без щелчков, пик
```

**Проверка на плате:**

- [ ] Слово «Миранда» → новый мягкий звон (восходящий, два тона), без щелчков.
- [ ] «Миранда, спроси меня что-нибудь» → колонка задаёт вопрос → звук
      «слушаю» → ответ принимается без слова пробуждения.
- [ ] Тишина 5 с после вопроса колонки → молча возвращается в ожидание.
- [ ] Запоздавший ответ большой модели (сложный вопрос, «…долго думает») → через
      время звон «внимание» и ответ целиком, с самого начала, без обрезанного
      первого слова.
- [ ] Объявление, пока говорите с колонкой (сложный вопрос, затем сразу
      «Миранда, …» и ещё вопрос) → разговор не прерывается звоном «внимание»,
      объявление звучит после.
- [ ] Ошибка (отключить сервер) → нисходящий звон; «думаю» — тихая капля.
- [ ] Громкость меняет и звуки, не только голос ответа.
- [ ] В журнале ядра колонка пишет `fw 0.3.0` (подтверждает, что залита новая прошивка).

## Ход ответа: событие `played`

Пока колонка говорит ответ, она раз в ~0,5 с шлёт ядру
`{"type":"played","turn":N,"bytes":B}` — сколько байт PCM ответа этого хода уже
отдано динамику (16 кГц, 16 бит, моно: 32000 байт в секунду), и последнее
`played` — прямо перед `playback_done`. По нему ядро знает, где сейчас речь
(мягкие прерывания на границе предложений). Это расширение протокола 3: номер
протокола тот же, старое ядро неизвестный `type` пропускает. При перебивании,
отмене хода и `stop_playback` итогового `played` нет.

**Проверка на плате** (тестовый сервер `tools/test_server` печатает все события):

- [ ] При запуске в Serial `SmartESP 0.4.0`.
- [ ] Вопрос → во время ответа в выводе сервера `played` примерно дважды в
      секунду, `bytes` растёт примерно на 16000 за раз, `turn` — номер хода.
- [ ] Перед `playback_done` — `played`, у которого `bytes` равен длине ответа:
      «ответ на ход N: X с» × 32000 (сервер шлёт кусками по 4096 байт — ровно).
- [ ] `python3 server.py --long` (очередь переполняется) → итоговый `bytes`
      меньше отправленного: считается только доигранное.
- [ ] «Миранда» во время ответа → `barge_in`, новых `played` старого хода нет.
- [ ] Вне ответа (покой, слушание вопроса, ожидание ответа) `played` не приходит.
- [ ] Обычное ядро (`core/`) с новой прошивкой работает как раньше: ответы,
      перебивание, объявления.

## Обновление по воздуху (прошивка 0.5.0, протокол 4)

С прошивки **0.5.0** колонку больше не нужно подключать по USB: ядро присылает ей команду
`update`, колонка сама скачивает файл с ядра (`http://<ядро>:<порт>/device/files/<токен>`,
одноразовая ссылка на 15 минут), считает SHA-256 и после успеха перезагружается. **Первый раз
0.5.0 прошивается по USB**, как раньше.

- **Прошивка.** Приложение → колонка → «Обновить прошивку…» → файл `.bin`: его кладёт
  `tools/build.sh` в `firmware/build/SmartEsp.ino.bin` (или Arduino IDE: «Скетч → Экспорт
  бинарного файла»). Новая прошивка пишется во вторую половину флеша (`app0`/`app1` по 3 МБ),
  загрузка переключается только после полной записи и проверки — при обрыве колонка остаётся на
  старой. Сейчас прошивка занимает ~2,86 МБ из 3 МБ.
- **Модель слова.** Вкладка «Обучение» → «Прогоны» → «На колонку». Модель (десятки КБ) и её порог,
  окно и арена сохраняются в LittleFS (раздел `spiffs`, 6 МБ; при первой загрузке 0.5.0 он
  форматируется — до ~10 с); при загрузке колонка берёт сохранённую модель, а если её нет или она
  не запустилась — встроенную. Прошивку для этого пересобирать не нужно.
- Ход обновления виден в панели колонки; события колонки — `update_status`
  (`progress` раз в ~0,5 с, затем `done` или `failed` с причиной: `download`, `size`, `hash`,
  `write`, `storage`, `busy`). Скачивание идёт в своей задаче — колонка в это время работает.
- Модуль — `src/updater/` (библиотеки `HTTPClient`, `Update`, `LittleFS` — из ядра платы, новых
  зависимостей нет). Дизайн — `docs/superpowers/specs/2026-11-22-ota-design.md`.

## Свои звуки колонки (прошивка 0.6.0, возможность `sounds`)

Сигналы колонки (`wake`, `listen`, `thinking`, `attention`, `error`) можно заменить своими
звуками из приложения: панель колонки → «Звуки» → «Заменить…», «Прослушать», «Встроенный»,
«Скопировать на другие колонки». Звуки задаются каждой колонке отдельно; колонку не в сети тоже
можно менять — она получит звуки при подключении. Ядро готовит звук (16 кГц моно, не длиннее
3 с, тишина по краям обрезана, громкость как у встроенных) и само доставляет его — при
подключении и после каждого изменения; у каждого сигнала видно «на колонке», «ждёт подключения
колонки», «доставляется» или «ошибка: … · Повторить».

- **Протокол.** Звуки — не номер протокола, а возможность в `hello`:
  `"caps":["sounds"],"sounds":{"wake":"<sha256>",…}` (хэши сохранённых звуков; встроенных
  нет в списке). Ядро шлёт звуки только колонке с `sounds` в `caps`: старая прошивка
  незнакомый `what` отбросила бы. Поставить звук —
  `{"type":"update","what":"sound","tone":"wake","path":"/device/files/<токен>","size":N,"sha256":"…"}`,
  вернуть встроенный — `{"type":"update","what":"sound","tone":"wake","size":0}`. Итог —
  `update_status` с `"what":"sound","tone":…`; перезагрузки нет.
- **На колонке** (`src/updater/SoundFiles.*`): `/sounds/<tone>.pcm` (PCM 16 кГц моно s16le,
  ≤ 96 000 байт) и `/sounds/<tone>.sha` в LittleFS; запись — во временный файл, проверка
  SHA-256, переименование. При загрузке сохранённые звуки читаются в PSRAM и через
  `SmartEsp.ino` уходят в `audio_out` (`setSound`) и `server_link` (`setSoundHash`, для
  `hello`). Новый звук подменяется сразу, когда тон не звучит. Испорченный файл удаляется —
  играет встроенный.
- Встроенные звуки для «Прослушать» — `ui/public/sounds/*.wav`; их пишет
  `tools/make_sounds.py` вместе с `SoundData.cpp`.
- Дизайн — `docs/superpowers/specs/2026-11-22-sounds-design.md`.

**Проверка на плате:**

- [ ] Прошить 0.6.0 (по воздуху или USB) → в Serial `SmartESP 0.6.0`, в панели колонки «Звуки»
      без подсказки про прошивку.
- [ ] «Заменить…» у «Слово услышано» (короткий MP3) → в журнале ядра `Звук wake на …: свой`,
      в Serial `updater: звук … готово` без перезагрузки; «Кузя» → играет новый звук.
- [ ] Громкость меняет и свой звук; звук длиннее 3 с → уведомление «обрезан».
- [ ] Перезагрузить колонку → свой звук остался; ядро при подключении ничего не досылает
      (хэши совпали).
- [ ] «Встроенный» → снова встроенный звон без перезагрузки.
- [ ] Замена на одной колонке → вторая звучит по-прежнему; «Скопировать на другие колонки» →
      вторая получает тот же набор.
- [ ] Колонка не в сети во время замены → после подключения получает звук сама.

## Музыка на колонках (прошивка 0.6.0, протокол 5)

С прошивки **0.6.0** колонка играет **музыку**: файлы из папок Mac, интернет-радио и звук Mac
(Spotify, Яндекс Музыка, YouTube через BlackHole). Голосом — коннектор `connectors/music`
(«Кузя, включи Кино на кухне», «пауза», «дальше», «громче», «включи звук с Мака», «выключи»), в
приложении — блок «Музыка» в панели колонки. Дизайн — `docs/superpowers/specs/2026-11-22-music-design.md`.

- **Как.** Ядро шлёт `{"type":"stream_start","stream":N,"path":"/device/stream/<токен>","rate":16000,
  "volume":0.6,"live":false}`; модуль `src/stream_player/` сам качает PCM (16 кГц, 16 бит, моно)
  по HTTP/1.0 с ядра (адрес — тот же, что у связи с ядром) в своей задаче в буфер 3 с (PSRAM), начинает после
  0,5 с запаса. Темп задаёт TCP. `audio_out` смешивает музыку под голосом и звуками, образец для
  эхоподавления — уже смесь. Ещё команды: `stream_stop {stream}` (0 — любой) и
  `stream_volume {value}` — громкость музыки относительно общей (`volume`).
- **Слово пробуждения.** Пока сценарий не в покое (слово, вопрос, ответ, объявление), музыка
  глохнет сразу (30 мс) и возвращается через 1,5 с покоя (нарастание 0,3 с). Обычный поток стоит
  на паузе, буфер цел; живой (`live`: радио, звук Mac) читается дальше без звука.
- **Отчёты** `{"type":"stream_status","stream":N,"state":"playing|ended|stopped|failed",
  "played":байт,"error":""|"download"|"rate"}`: `playing` раз в ~1 с, `played` — сколько PCM
  отдано динамику (по нему ядро продолжает с места паузы). Связь с ядром пропала — поток стоп.
- Частота — 16000 (прошивка 0.6.0) или 48000 (0.7.0, см. «Звук 48 кГц»); другая — `failed`/`rate`.
- Новых библиотек нет (`HTTPClient` — из ядра платы). Прошивка — 2 860 971 байт (90% раздела 3 МБ; 0.5.0 — 2 856 143).

**Проверка на плате** (ядро с колонкой 0.6.0, коннектор «Музыка на колонках» включён, папка задана):

- [ ] В Serial `SmartESP 0.6.0`, в журнале ядра колонка с `protocol 5`.
- [ ] «Кузя, включи музыку» → через ~1 с играет первый файл; в Serial `stream_player: поток N`.
- [ ] «Кузя» во время музыки → музыка стихает сразу, сигнал слова слышен, вопрос распознаётся
      (не путается с музыкой); после ответа через ~1,5 с музыка продолжается с того же места.
- [ ] Уточняющий вопрос Кузи («Какую песню?») → музыка не возвращается между вопросом и ответом.
- [ ] Громкая музыка не будит колонку сама (нет ложных «Кузя»).
- [ ] «Пауза» → тишина; «продолжи» → с того же места (±1 с); «дальше», «назад» — другой трек.
- [ ] «Громче», «тише» — меняется только музыка, голос Кузи — как был.
- [ ] Файл доиграл → следующий без щелчков; очередь кончилась → тишина, в приложении «Не играет».
- [ ] Радио: «включи радио» → играет; «Кузя» → тишина, после ответа радио «сейчас».
- [ ] Звук Mac: BlackHole, «включи звук с Мака» → звук Spotify на колонке с задержкой ~1 с.
- [ ] Объявление таймера во время музыки → музыка стихает, объявление, музыка продолжается.
- [ ] Выключить ядро → музыка останавливается (связь пропала); ядро 0.5.x-протокола — колонка
      работает как 0.5.0.
- [ ] Минута музыки — в Serial нет `audio_in: буфер переполнен` и `voice_frontend: AFE не успевает`.

## Звук 48 кГц и калибровка эха (прошивка 0.7.0)

**0.7.0 — та прошивка, которую один раз нужно залить по USB**: вместе с ней приходит новая
разметка флеша (две копии по 4 МБ, см. «Сборка в Arduino IDE»). Дальше — по воздуху.
Дизайн — `docs/superpowers/specs/2026-11-23-hifi-design.md`.

- **Динамик всегда 48 кГц.** Голос, звуки и ответ (16 кГц) идут через многофазный фильтр ×3,
  музыка 48 кГц — напрямую (16 кГц — тоже через ×3). Частота на лету не меняется. Смесь 48 кГц
  через фильтр ÷3 (до ~7 кГц) становится образцом 16 кГц для эхоподавления. Фильтры —
  `src/audio_out/Resampler.*` (96 отводов, окно Кайзера; зеркала и наложения ниже −60 дБ).
- **Потоки 48 кГц.** В hello колонка шлёт `"stream_rates":[16000,48000]`; ядро выбирает
  наибольшую общую частоту и просит её у ffmpeg. Колонка 0.6.0 — по-прежнему 16 кГц. Поток
  48 кГц — 768 кбит/с, буфер 3 с — 288 КБ PSRAM.
- **Сдвиг образца** (на сколько задержать звук динамика перед эхоподавлением) хранится в NVS,
  по умолчанию **20 мс** (очередь DMA динамика на 48 кГц — 30 мс вместо 90 мс на 16 кГц, а на
  16 кГц на плате подобрали 80 мс). Модуль — `src/echo_calibrator/`.
- **Калибровка** — приложение → колонка → «Калибровка эха»: колонка 1,5 с играет шум, пишет
  микрофон и образец, в своей задаче находит взаимной корреляцией, насколько эхо позже образца,
  и сохраняет новый сдвиг (с опережением 5 мс). Итог и уверенность — в панели. В комнате при
  этом должно быть тихо, громкость колонки — обычная.
- Протокол — тот же **5**: всё новое — возможность `echo` в `caps` и поле `stream_rates`.
  Команды `{"type":"echo_calibrate"}` и `{"type":"echo_delay","delay_ms":0..300}`, событие
  `{"type":"echo_status","state":"current|running|done|failed","delay_ms":N,"previous_ms":N,
  "confidence":0..1,"error":""|"busy"|"quiet"|"weak"}` (`current` — при каждом подключении).
- Прошивка — 2 872 599 байт (68% слота 4 МБ; в старый слот 3 МБ — 91%).

**Как откалибровать.** В приложении выберите колонку → «Калибровка эха», 2–3 секунды молчите.
«Готово: сдвиг N мс, уверенность X%» — сдвиг сохранён. «Не вышло: …» — сдвиг прежний; громче
колонку или тише в комнате и повторите. Потом **проверьте сами** (автоматически этого не
проверить):
1. Включите громкую музыку на колонке и скажите слово пробуждения с 2–3 м — колонка должна
   услышать.
2. Попросите длинный ответ на полной громкости — колонка не должна будить сама себя.
Если хуже, чем было на 0.6.0, — сдвиг можно задать вручную: `PUT /api/v1/devices/{id}/echo`
`{"delay_ms": N}` (шаг 5 мс), и напишите, какой подошёл.

**Как откатиться на 16 кГц.** Последняя прошивка 16 кГц помечена тегом `fw-0.6.0`:

```bash
git worktree add /tmp/fw-0.6.0 fw-0.6.0
cp /tmp/fw-0.6.0/firmware/SmartEsp/secrets.example.h /tmp/fw-0.6.0/firmware/SmartEsp/secrets.h
# вписать в него Wi-Fi и IP Mac: прошивкам до 0.8.0 адреса зашиваются
/tmp/fw-0.6.0/tools/build.sh      # образ: /tmp/fw-0.6.0/firmware/build/SmartEsp.ino.bin
```

и поставьте его по воздуху: приложение → колонка → «Обновить прошивку…». Образ прошивки не
содержит таблицы разделов, поэтому на новой разметке 0.6.0 работает; сдвиг в NVS она не читает.

**Проверка на плате:**

- [ ] В Serial `SmartESP 0.7.0` и `echo_calibrator: сдвиг образца 20 мс` (после калибровки — свой).
- [ ] Голос ответа и сигналы — без треска и «металла», громкость как на 0.6.0.
- [ ] Музыка из папки (FLAC/MP3 44,1 кГц) — заметно ярче, без щелчков; в журнале ядра поток с
      `rate` 48000.
- [ ] «Калибровка эха» → шум ~1,5 с → «Готово», уверенность ≥ 50%, сдвиг ~15–30 мс; повтор —
      тот же сдвиг ±2 мс; после перезагрузки сдвиг тот же.
- [ ] Слово во время громкой музыки с 2–3 м — слышно; длинный ответ не будит колонку сам.
- [ ] Минута музыки и разговор — в Serial нет `audio_in: буфер переполнен`, `voice_frontend:
      AFE не успевает`, `voice_frontend: loop() не забирает звук слова`.
- [ ] Ядро без этой ветки (колонка 0.7.0 со старым ядром) — колонка работает, музыка 16 кГц.

## Сеть: Wi-Fi с телефона и поиск ядра (прошивка 0.8.0)

С 0.8.0 в прошивке не зашито ничего: ни Wi-Fi, ни адрес Mac (`secrets.h` больше не нужен).
Дизайн — `docs/superpowers/specs/2026-11-26-discovery-design.md`.

- **Имя колонки** — `kuzya-xxxx.local` (xxxx — 4 последних знака MAC), его же видно в роутере.
- **Wi-Fi с телефона.** Нет сохранённой сети или 2 минуты не удаётся к ней подключиться — колонка
  поднимает открытую точку Wi-Fi **`Kuzya-xxxx`**. Подключитесь к ней с телефона: страница
  настройки откроется сама (если нет — откройте `http://192.168.4.1`). Выберите сеть, введите
  пароль, «Сохранить»; страница покажет «Подключено…», через 15 с точка закроется. Сеть
  сохраняется во флеше колонки (NVS), когда к ней удалось подключиться. Пока точка открыта,
  колонка продолжает пробовать сохранённую сеть.
- **Поиск ядра.** Ядро объявляет себя в сети по Bonjour (служба `_smartesp._tcp`, TXT `id`,
  `path=/device`, `version`; модуль `core/smartesp/discovery`), постоянный id ядра — в
  `~/SmartEsp/core_id`. Колонка ищет службу по mDNS (модуль `src/core_finder/`, своя задача),
  когда нет связи с ядром: сразу, затем через 5, 10, 20, 30 с. Сменился IP Mac — ядро
  переобъявится (сверка адресов раз в 30 с), колонка найдёт его заново. Несколько ядер — колонка
  берёт то, с которым работала в прошлый раз (id во флеше); если его нет три поиска подряд —
  первое найденное. У Mac несколько адресов (VPN, мост ВМ) — колонка берёт адрес из своей подсети.
- **Переход с 0.7.0 по воздуху.** Своей сохранённой сети у колонки ещё нет, поэтому 0.8.0 сначала
  берёт сеть, которую запомнила библиотека Wi-Fi ESP32 (её записала 0.7.0), и, подключившись,
  сохраняет как свою. Телефон нужен, только если и это не вышло. **Сначала обновите ядро**
  (иначе колонке 0.8.0 некого искать), потом колонку.
- **Тестовый сервер** (`tools/test_server`) себя не объявляет — объявите его вручную на время
  проверки: `dns-sd -R smartesp-test _smartesp._tcp local 8765 id=test path=/device`.

**Проверка на плате:**
- [ ] Чистая колонка (или «Erase All Flash» при прошивке по USB) → в Serial `wifi: сети нет —
      точка настройки`, у телефона видна сеть `Kuzya-xxxx`; подключение → страница настройки
      открылась сама, в списке — домашняя сеть.
- [ ] Выбрать сеть, пароль, «Сохранить» → «Подключено к …, адрес колонки …», через ~15 с точка
      пропала; в Serial `net_settings: сохранена сеть …`, `core_finder: ядро … — <IP Mac>:8765`,
      `server_link: connected`; в приложении колонка на связи.
- [ ] Перезагрузка колонки → подключается сама, точки нет.
- [ ] Смена IP Mac (другой адрес в настройках сети или переподключение к сети) → в журнале ядра
      `Объявление в сети: … <новый IP>` (до 30 с); колонка через несколько секунд снова на связи.
- [ ] Колонка 0.7.0 → «Обновить прошивку…» 0.8.0 → после перезагрузки в Serial `своей сети нет,
      пробую сеть прошлой прошивки …`, `net_settings: сохранена сеть …`, колонка на связи без
      телефона.
- [ ] Неверный пароль на странице → через ~20 с там же «Не удаётся подключиться… Проверьте пароль»,
      точка не закрывается. Сменить пароль роутера (или выключить его) у работающей колонки →
      через 2 мин снова точка `Kuzya-xxxx`; вернуть роутер → колонка подключается, точка закрывается.
- [ ] `ping kuzya-xxxx.local` с Mac отвечает.
- [ ] В разговоре и под музыку, пока колонка ищет ядро или открыта точка, в Serial нет
      `audio_in: буфер переполнен`.

## Ядро на Mac

Настоящий сервер — ядро в папке `core/` (Python): распознаёт речь, отвечает
локальной моделью через Ollama и озвучивает ответ. Установка, настройка колонок
и запуск — в [`core/README.md`](core/README.md). Без платы ядро проверяется
поддельной колонкой `tools/fake_device.py`: вопрос из WAV, ответ — в WAV.

## Тесты логики на ноутбуке

```bash
tools/host_tests/run.sh
```

Проверяют сценарий (`session`), протокол (`server_link`), признаки слова
пробуждения (`wake_word`: совпадают с `pymicro-features`), точку настройки Wi-Fi
(`wifi_link`: когда открывать, форма, страница) и выбор ядра (`core_finder`) без платы.
Нужен clang++ и ArduinoJson (см. комментарий в `run.sh`).
