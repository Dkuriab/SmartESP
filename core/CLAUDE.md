# SmartESP core — правила ядра

Ядро домашнего голосового ассистента: Python 3.12, один процесс `asyncio`,
проект на `uv`. Общие правила репозитория (git, секреты, оформление) —
в корневом `../CLAUDE.md`.

## Команды

Все — из папки `core/`:

```
uv sync                  # установить зависимости (по uv.lock)
uv run pytest            # тесты (без железа и моделей)
uv run ruff check        # линтер (включая сложность C901)
uv run ruff format       # форматирование
uv run pyright           # типы (strict для contracts/)
```

## Структура

```
core/
  pyproject.toml, uv.lock
  smartesp/
    contracts/           ← только типы и протоколы (аналог Types.h)
    devices/ stt/ stages/ conversation/ executors/ tts/ config/
    tools/               ← MCP-хаб: коннекторы — подпроцессы stdio, их инструменты (ToolBox), объявления
    notify/              ← речь по инициативе: очередь объявлений по колонкам, повторы, срок доставки
    fileplay/            ← звуковой файл на колонке: разбор по ходу (ffmpeg), ход ядра, итог событием
    people/ tasks/       ← (будут)
    events/              ← шина событий: лента для интерфейса, у подписчика ограниченная очередь
    control/             ← управление ядром: состояние, применение правок настроек на лету
    api/                 ← HTTP/WebSocket API `/api/v1`, токен (и его сокрытие в журнале), журнал для интерфейса, раздача интерфейса
    lifecycle/           ← цикл asyncio, честная остановка, файл запуска, слежение за родителем
    kinds.py             ← реестры реализаций по kind и перевод настроек в части (связка)
    sections.py          ← разделы настроек, применяемые на лету (связка)
    parts.py             ← группы частей для wiring: разговор, живой исполнитель, голос, пульт (связка)
    wiring.py            ← сборка частей; прогрев и остановка — вызовы модулей
    main.py              ← связка (аналог SmartEsp.ino)
  tests/
  fakes/                 ← поддельные реализации договоров
```

## Правила

- **Модуль** — папка-пакет `smartesp/<module>/`. Публичное — только то, что
  экспортирует его `__init__.py`. Остальное — внутреннее.
- **Модули не импортируют друг друга.** Общие типы и договоры (протоколы
  `typing.Protocol`) — только в `smartesp/contracts/`: там нет логики, только
  dataclass'ы и протоколы.
- **Связка — `smartesp/main.py`**: создаёт модули по конфигурации и соединяет
  их. Своей логики в нём нет. Единственное место, где видно, кто с кем работает.
- **Сменные части — за договором и в реестре.** STT, TTS, обработчик,
  исполнитель, хранилище — реализации протокола из `contracts`, которые
  регистрируются под именем (`"whisper"`, `"piper"`, `"ollama"`). Конфигурация
  выбирает реализацию по имени. Новая реализация = новый файл + одна строка
  регистрации; остальной код не меняется.
- **Возможности — только через MCP.** В ядре нет кода про лампочки, заметки,
  напоминания и т. п.
- **Размеры:** файл ≤ 300 строк, функция ≤ 50 строк, модуль ≤ ~1000 строк.
  Вырос — делим. Цикломатическая сложность функции ≤ 10 (`ruff` C901).
- **Типы строгие:** `pyright` в режиме strict для `contracts/` и публичных
  интерфейсов модулей.
- **Async везде.** Тяжёлое (STT, TTS, узнавание голоса) — в пуле
  потоков/процессов, чтобы не блокировать цикл.
- **Тесты без железа и моделей:** у каждого договора есть поддельная
  реализация (`fakes/`), каждый модуль тестируется с подделками. Тесты с
  настоящими моделями помечены `@pytest.mark.models` и по умолчанию
  пропускаются (`pytest -m models` — запустить). Плюс сквозной тест:
  поддельная колонка → ядро с подделками → ожидаемый звук ответа.
- **Зависимости зафиксированы** (`uv.lock`, версии в `pyproject.toml` через
  `==`); новая библиотека — в том же PR.
- **Оформление:** имена на английском, комментарии и docstring'и на русском.
  `snake_case` для функций, переменных и файлов; `PascalCase` для классов;
  `UPPER_SNAKE_CASE` для констант.
  `ruff format` + `ruff check`.
- **Git** — как для прошивки: ветка + PR, описание на русском
  (Что / Зачем / Как проверить).
