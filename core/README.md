# SmartESP core

Ядро домашнего голосового ассистента (сервер на Mac): принимает речь с
колонок ESP32, распознаёт, отвечает через локальную модель и озвучивает.
Дизайн: `../docs/superpowers/specs/2026-11-18-core-design.md`.

## Установка

Нужны `uv` и Python 3.12 (`uv python install 3.12`).

```
cd core
uv sync
```

`mlx-whisper` тянет `torch` — установка долгая, это нормально.

## Проверка

```
uv run pytest
uv run ruff check && uv run ruff format --check
uv run pyright
```

## Голос

Голоса скачиваются сами: при старте и при выборе нового голоса (отдельных
скриптов нет). Голос по умолчанию — Silero «xenia».

| Вид | Голоса | Размер | Скорость на фразу | Лицензия |
|---|---|---|---|---|
| `silero` | xenia, baya, kseniya | ~145 МБ | ~0,03 с | CC BY-NC-SA: **только некоммерческое использование** |
| `vosk` | female_0, female_1, female_2 | ~900 МБ | ~0,46 с | Apache 2.0 |
| `piper` | ru_RU-irina-medium (и другие `.onnx` в `voices/`) | ~63 МБ | ~0,07 с | MIT |

Голос выбирается в приложении или в `config.yaml`:

```yaml
tts: {kind: vosk, voice: female_1}
```

Голос открывается в фоне при старте, ядро не ждёт скачивания. Пока нужный голос
качается (или нет интернета), ядро говорит уже скачанным голосом — выбранным, если
он есть, иначе любым другим — и пишет об этом в журнал. Скачивание повторяется
через 30 с, 2 мин, 5 мин, дальше каждые 5 мин; когда голос готов, ядро
переключается на него само. Если скачанных голосов нет совсем, ядро всё равно
стартует, но колонки получают сигнал ошибки, пока голос не появится.

## Запуск

```
cd core
uv run python -m smartesp
```

`python -m smartesp` запускают из `core/`: это виртуальный проект uv (пакет не
установлен в окружение), и из другой папки модуль `smartesp` не найдётся.

Флаги:
- `--parent-watch` — остановиться, когда родитель закроет stdin (так ядро
  запускает приложение, чтобы ядро не осталось без хозяина);
- `--openapi PATH` — записать схему OpenAPI в файл и выйти (сервер не
  стартует, ничего не греется).

Перед запуском должна работать Ollama (`ollama serve` или приложение) с моделью
из `config.yaml` (`ollama pull <модель>`). Если Ollama недоступна, ядро всё равно
стартует (в журнале «Ollama недоступна: …»), но на вопросы колонка будет
отвечать сигналом ошибки.

Первый запуск:
- создаётся `~/SmartEsp/config.yaml` — пустой, с подсказками (см. «Настройки»);
- mlx-whisper скачивает модель распознавания (~1,6 ГБ) в кеш Hugging Face —
  первый старт долгий, дальше модель берётся из кеша.

При старте ядро прогревает модели (в журнале «Исполнитель прогрет…»,
«STT прогрет…»), затем слушает колонки на `ws://<mac>:8765/device`
(адрес и порт — `server` в `config.yaml`). Сервер поднимается сразу, прогрев
идёт в фоне: пока состояние `warming`, колонка на фразу получает сигнал ошибки.
Остановка — Ctrl+C.

## Настройки

В `~/SmartEsp/config.yaml` лежит только то, что вы поменяли сами; всё остальное
ядро берёт из своих значений по умолчанию, поэтому новые возможности появляются
сами, без правки файла. Все значения по умолчанию — рядом, в
`config.defaults.yaml` (только для справки, ядро перезаписывает его при старте):
чтобы что-то поменять, перенесите ключ оттуда в `config.yaml` и перезапустите ядро
(или меняйте настройки через API — см. «Приложение и API»).

Файл прежнего формата (все настройки целиком) ядро при первом старте переводит
само: оставляет только ваши изменения, старый файл сохраняет как `config.yaml.bak`.

### Что меняется на лету

Настройки, изменённые через `PATCH /api/v1/config`, ядро применяет без перезапуска
и сразу записывает в `config.yaml`:

- **на лету:** `devices`, `tts`, `executors`, `stages`, `history`;
- **требуют перезапуска:** `server`, `stt`, `arbitration` — такая правка
  записывается, ответ получает `status: restart_required`, а `GET /status`
  показывает `restart_required: true`, пока ядро не перезапустят.

Смена голоса или модели при звучащем ответе ничего не обрывает: идущий ход
договаривает старыми частями, следующий берёт новые, старая модель выгружается из
Ollama после конца хода. Новая модель сначала прогревается (до 120 с), и только
потом подменяет старую. Несколько быстрых правок применяются по очереди, в
`config.yaml` остаётся последняя успешная. Правка файла `config.yaml` руками на
лету не подхватывается — нужен перезапуск.

## Приложение и API

Ядро отдаёт интерфейс на `/` (собранный `ui/dist`; без сборки — страница с
командой сборки) и API на `/api/v1`. Колонки ходят на `/device` — без токена.

**Токен.** Весь API закрыт токеном (нужен и с `127.0.0.1`). Ядро создаёт его при
первом старте в `~/SmartEsp/token` (права `0600`, `secrets.token_urlsafe(32)`).
HTTP — заголовок `Authorization: Bearer <token>`, WebSocket — `?token=<token>`.
Без токена или с чужим — 401 (для WebSocket закрытие с кодом 4401).

**Файл запуска.** Сразу после подъёма сервера ядро пишет
`~/SmartEsp/run/core.json` — `{"port": …, "pid": …, "started_at": …}`; по нему
приложение находит порт и pid. При остановке файл удаляется.

Примеры:

```
curl -H "Authorization: Bearer $(cat ~/SmartEsp/token)" http://127.0.0.1:8765/api/v1/status
curl -X PATCH -H "Authorization: Bearer $(cat ~/SmartEsp/token)" \
  -H "Content-Type: application/json" \
  -d '{"tts": {"kind": "vosk", "voice": "female_1"}}' http://127.0.0.1:8765/api/v1/config
```

Ресурсы (все пути — с префиксом `/api/v1`):

| Запрос | Что делает |
|---|---|
| `GET /status` | версия, `uptime_s`, `state` (`warming`, `ready`, `stopping`), Ollama (`reachable`, `loaded`), колонки, голос (`state`: `ready`, `downloading`, `failed`, `missing`), `applying`, `restart_required` |
| `GET /config` | `effective` — настройки целиком, `overridden` — изменённые ключи через точку (`tts.kind`), `restart_sections` |
| `PATCH /config` | частичные настройки в форме `config.yaml`: словари сливаются вглубь, списки заменяются целиком, `null` сбрасывает ключ к умолчанию. Ответ `{change_id, status, error}`: `accepted` или `restart_required` — 200, `invalid` — 422, `stopping` — 503 |
| `GET /models` | модели Ollama: `{name, size_bytes}` (Ollama недоступна — 502) |
| `GET /voices` | голоса: `{kind, voice, title, size_mb, downloaded, current}` |
| `POST /voices/download` | `{kind, voice}` → 202, `{change_id, status: "accepted"}`; ход скачивания — события `voice_download`, `voice_ready` |
| `POST /voices/preview` | `{kind, voice, style="normal", text=null}` → `audio/wav` (16 кГц, 16 бит, моно); голос не скачан — 409 |
| `GET /turns?limit=100` | последние ходы (данные `turn_finished`), от новых к старым; ядро хранит 100 последних в памяти |
| `POST /restart` | перезапуск ядра, ответ 202 |
| `WS /events?token=` | поток событий JSON `{"kind", "data", "at"}`: `core_state`, `device_connected`, `device_disconnected`, `wake`, `arbitration`, `turn_started`, `turn_heard`, `turn_finished`, `change_applied`, `voice_download`, `voice_ready` |

Схема OpenAPI для интерфейса: `uv run python -m smartesp --openapi ../ui/openapi.json`.

## Остановка и перезапуск

Остановка (Ctrl+C, SIGTERM, закрытый stdin при `--parent-watch` или
`POST /restart`) идёт по порядку и занимает не дольше 15 с:

1. состояние `stopping`; новые фразы, подключения колонок и правки настроек не
   принимаются (колонка на фразу получает сигнал ошибки);
2. идущие ответы договариваются — до 10 с, потом обрываются;
3. колонки отключаются;
4. каждая загруженная модель выгружается из Ollama (ждём не дольше 1 с на модель);
5. файл `run/core.json` удаляется, процесс выходит с кодом 0.

Повторный Ctrl+C во время остановки — немедленный выход.

`POST /restart` делает ту же остановку и затем запускает ядро заново (с теми же
флагами). Если одновременно пришла просьба выйти (сигнал, закрытый stdin),
перезапуска нет — ядро просто выходит.

## Колонки

Колонка представляется ядру MAC-адресом Wi-Fi: `device_id` в `hello`,
заглавными через двоеточие (`AA:BB:CC:DD:EE:FF`). MAC видно в журнале ядра при
подключении: `device AA:BB:CC:DD:EE:FF connected from …`. Имя колонки (модель
его видит: «Колонка: Кухня») задаётся в `config.yaml`, ключ — MAC **в кавычках**:
MAC из одних цифр без кавычек YAML прочтёт как число, и ядро не запустится
(«неверные настройки»).

```yaml
devices:
  "AA:BB:CC:DD:EE:FF":
    name: Кухня
  "11:22:33:44:55:66":
    name: Спальня
```

## Обработчики фразы

Обработчики смотрят на фразу и добавляют пометки в промпт модели; список — `stages`
в `config.yaml`. Сейчас есть один:

- `whisper_detect` — шёпот. Вопрос сказан шёпотом (слово «Hi, ESP» — обычным
  голосом) → пометка «Человек говорит шёпотом», модель начинает ответ меткой
  `[style:quiet]`, и колонка отвечает тихо. В журнале на каждую фразу:
  `шёпот: да/нет (… доля тона 0.85)`, у хода — `пометки […]` и `стиль quiet`.

Обработчик включён по умолчанию; выключить — задать в `config.yaml` `stages: []`.
Правило для модели («на пометку о шёпоте отвечай меткой `[style:quiet]`») обработчик
приносит сам: ядро добавляет правила включённых обработчиков к системному промпту
диспетчера, в настройках их писать не нужно.

## Где что лежит

Папка данных — `~/SmartEsp` (или `$SMARTESP_HOME`):
- `config.yaml` — ваши изменения настроек (колонки, модели, голос…);
- `config.defaults.yaml` — все значения по умолчанию, для справки;
- `token` — токен API (права `0600`);
- `run/core.json` — порт и pid работающего ядра (есть только пока ядро запущено);
- `voices/` — скачанные голоса (Piper, Silero, Vosk);
- `logs/core.log` — журнал (5 файлов по 1 МБ, плюс вывод в консоль). Каждый
  ход — строка с вопросом, ответом и задержками `stt_ms`, `first_text_ms`,
  `first_audio_ms`.

Поддельная колонка задаёт вопрос из WAV (16 кГц, 16 бит, моно) и печатает
ответ ядра (из корня репозитория, при запущенном ядре):

```
uv run --project core python tools/fake_device.py --wav core/tests/data/privet.wav --out reply.wav
```
