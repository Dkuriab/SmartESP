# Telegram-бот SmartESP

Отдельная программа, чтобы говорить с Кузей с телефона, когда вы не дома.
Не часть ядра и не часть приложения: бот — обычный клиент API ядра
(дизайн — `docs/superpowers/specs/2026-11-19-food-telegram-design.md`, 2.2–2.3).

- Текст → ответ Кузи текстом.
- Голосовое → ядро распознаёт речь → ответ текстом.
- Фото штрихкода (можно с подписью «200 г») → бот сам находит штрихкод
  (EAN-13, EAN-8, UPC) и отправляет Кузе текст «штрихкод 4601234567893, 200 г».
  Штрихкода не видно — «Не вижу штрихкод на фото. Сфотографируй его ближе.»
- Пока Кузя думает, в чате видно «печатает…».
- Отвечает только людям из списка в настройках; остальным — молчание.
  Пишет только в личном чате, группы не слушает.

Связь с Telegram — только исходящие запросы (long polling): порты на Mac не
открываются, вебхуков нет. Сообщения проходят через серверы Telegram.

## 0. Проще всего — из приложения

Ядро само запускает бота и держит его (перезапуск при падении), если включить его в приложении:
список слева → «Клиенты» → «Telegram-бот». В его панели — токен бота (скрытое поле) и «Кому
отвечать» (`user_id=имя;…`). Адрес и токен ядра бот получает от ядра сам. Кто напишет боту, появится
в панели строкой «Написал(а) боту: Аня (id 123)» с кнопкой «Добавить». Внизу панели — журнал бота.
На схеме бот — источник ходов рядом с колонками: ход из Telegram подсвечивает его.

Если бот уже запущен из терминала — остановите его: два бота на одном токене мешают друг другу.
Заполненное в приложении важнее `settings.toml`; пустое — берётся из файла (можно не переносить).

## 1. Создать бота

1. В Telegram открыть [@BotFather](https://t.me/BotFather), отправить `/newbot`.
2. Придумать имя и адрес бота (адрес оканчивается на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...` — это `telegram.bot_token`.
   Токен никому не показывайте: с ним любой может говорить от имени бота.

## 2. Настройки

```bash
cd clients/telegram
cp settings.example.toml settings.toml
```

`settings.toml` в git не попадает (секреты). Заполнить:

| Ключ | Что это |
|------|---------|
| `telegram.bot_token` | токен от BotFather |
| `core.url` | адрес ядра; ядро на этом же Mac — `http://127.0.0.1:8765` (по умолчанию) |
| `core.token` | токен ядра: содержимое файла `~/SmartEsp/token` (или `$SMARTESP_HOME/token`) |
| `[users]` | кто допущен: `user_id = "имя"`; имя уходит ядру как человек хода |

Свой `user_id` проще всего узнать у самого бота: запустите его (раздел 3) с
любым числом в `[users]`, напишите боту — в журнале появится строка
`Сообщение от недопущенного user_id=123456789 пропущено`. Впишите это число:

```toml
[users]
123456789 = "Имя"
```

и перезапустите бота.

## 3. Запуск

Нужен `uv` (как для ядра) и запущенное ядро.

```bash
cd clients/telegram
uv sync
uv run telegram-bot                       # настройки из clients/telegram/settings.toml
uv run telegram-bot --settings путь.toml  # или из другого файла
```

Остановить — `Ctrl+C`. Нет файла настроек или он неверный — бот объяснит, что
поправить, и выйдет с кодом 2.

Что бот отвечает, когда что-то не так:
- ядро не запущено или не ответило за 60 с — «Кузя сейчас недоступен.»;
- ядро не приняло токен — «Кузя не пускает бота — проверь токен.» (и ошибка в журнале);
- ядро отклонило запрос (например, не разобрало голосовое) — «Не получилось
  разобрать сообщение — попробуй ещё раз.»

## 4. Как бот говорит с ядром

Бот — HTTP-клиент ядра (`telegram_bot/core_client.py`). Каждый запрос несёт
заголовок `Authorization: Bearer <core.token>`, как остальные ресурсы `/api/v1`.
Ограничение на весь запрос — 60 секунд. Прокси из окружения не используются.

### `POST /api/v1/ask` — ход текстом

Запрос, `Content-Type: application/json`:

```json
{"text": "штрихкод 4601234567893, 200 г", "person": "Имя", "source": "telegram", "account": "123456789"}
```

- `text` — непустая строка: текст сообщения или «штрихкод <цифры>[, <подпись>]»;
- `person` — имя человека из `[users]`;
- `source` — всегда `"telegram"` (в ленте ядра — источник «Telegram»);
- `account` — `user_id` отправителя в Telegram строкой. Ядро ищет человека, связанного с
  этим аккаунтом во вкладке «Люди» («Связи»): нашло — ход идёт от его имени и с его
  постоянным id (заметки, таймеры, еда — его); нет — id `telegram:<user_id>` и имя из
  `person`. Голос в ходах через бота ядро не узнаёт: человека знает канал.

Ответ 200:

```json
{"answer": "Записала: ...", "turn_id": "..."}
```

Бот берёт только `answer` (строка; пустая → «Кузя ничего не ответил.»),
лишние поля игнорирует. Длинный ответ режется на сообщения по 4096 символов.

### `POST /api/v1/ask/voice` — ход голосом

Запрос `multipart/form-data`:
- `audio` — файл `voice.ogg`, `Content-Type: audio/ogg` (OGG/Opus, как его
  отдаёт Telegram);
- `person` — имя человека;
- `source` — `telegram`;
- `account` — `user_id` отправителя строкой (как у `/ask`).

Ответ — как у `/ask`: 200 `{"answer", "turn_id"}`.

### Ошибки

| Ответ ядра | Что делает бот |
|------------|----------------|
| 401, 403 | ошибка в журнал, в чат — «Кузя не пускает бота — проверь токен.» |
| 400, 413, 422 (`{"detail": "..."}`) | в чат — «Не получилось разобрать сообщение — попробуй ещё раз.» |
| любой другой код, не JSON, нет `answer`, нет соединения, дольше 60 с | в чат — «Кузя сейчас недоступен.» |

## 5. Разработка

```bash
uv run pytest -q             # тесты: без Telegram и без ядра (подделки)
uv run ruff check
uv run ruff format --check
uv run pyright
```

Устройство:

```
telegram_bot/
  settings.py     ← settings.toml → Settings, понятные ошибки
  core_client.py  ← HTTP-клиент ядра по договору выше
  barcode.py      ← штрихкод на фото (zxing-cpp + Pillow)
  assistant.py    ← логика без Telegram: доступ, ходы, ответы на ошибки
  bot.py          ← тонкая прослойка aiogram: доступ, «печатает…», скачивание файлов
  main.py         ← связка и точка входа telegram-bot
tests/            ← fakes.py: поддельное ядро и поддельная сессия Bot API
```

Зависимости зафиксированы в `pyproject.toml` (`==`) и `uv.lock`: aiogram 3.31.0,
aiohttp 3.14.5, httpx 0.28.1, zxing-cpp 3.1.1, Pillow 13.0.0.
