# food — дневник питания и калории для SmartESP

MCP-коннектор (stdio) для «Кузи»: записать съеденное голосом или по штрихкоду,
посчитать калории и белки/жиры/углеводы, подвести итоги.

## Инструменты

- `food_log(what, grams=0, barcode="", when="")` — записать съеденное.
  Калорийность ищется по порядку:
  1. своя база продуктов (по штрихкоду; без штрихкода — по названию);
  2. прошлые записи дневника, где продукт назван так же — по названию продукта или по
     словам человека («как вчера»: вчера на «гречка» выбрала «гречка (сухая)» — сегодня
     «гречка» сразу она);
  3. barcode-list.ru по штрихкоду — только название товара; оно сопоставляется со
     встроенной таблицей и своими продуктами (см. «Штрихкоды» ниже);
  4. встроенная таблица частых продуктов;
  5. не нашлось — «Не знаю калорийность «…». Скажи, сколько ккал на 100 г», запись не делается.

  (Open Food Facts — по желанию, `FOOD_OFF=1`: он спрашивается после своей базы и
  даёт калорийность сразу; ответ кэшируется в своей базе.)

  Штрихкод не помог (нет в справочнике, нет сети, неверные цифры), но есть
  название — ищется по названию (шаги 1, 2, 4) с пояснением в ответе.
  Молча записывается только точное совпадение с названием или синонимом. Неоднозначное
  («гречка» — сухая или варёная?) и частичное («рыба» → «лосось слабосолёный») —
  вопрос «Уточни: …» (до трёх вариантов); выбор сразу после вопроса запоминается.
  Вес: `grams`; можно и в `what` («гречка 150 г», «200 мл молока», «1,5 кг» — мл и л
  считаются как граммы). Штуки — числом в `what` («2 яйца», «два яйца») и только если
  вес штуки известен (в таблице) или у продукта есть вес упаковки; без веса и без
  штук берётся вес упаковки, если она не тяжелее 1 кг, иначе — просит граммы.
  Больше 2 кг или больше 20 штук за запись — не пишет, просит вес порции.
  `when`: пусто — сейчас; «вчера», «позавчера», «8:30», «вчера в 19:30», ISO-дата.
  Записей в будущем не бывает: время позже текущего больше чем на час — это вчера
  (в 00:30 «23:30» — вчерашний ужин).
  Ответ: «Записала: гречка (сухая), 150 г — 515 ккал. За сегодня 1340 ккал.»
- `product_add(name, kcal_100g, protein=0, fat=0, carbs=0, barcode="", pack_grams=0)` —
  продукт в свою базу (своё блюдо или штрихкод, который не нашёлся); то же название
  или штрихкод — обновляет.
- `food_today()` — сегодня: ккал, что ели, Б/Ж/У.
- `food_summary(days=7)` — за дни: всего, в среднем за день с записями, Б/Ж/У, по дням.
- `food_undo()` — убрать последнюю добавленную запись.
- `food_find(query)` — когда и сколько ел (до 5 последних записей).

Названия сравниваются без регистра, «ё» и окончаний («гречку», «гречки» → «гречка»).
Числа округляются: ккал — до целых, граммы и Б/Ж/У — до десятых.
Ответы — короткий русский текст для озвучки.

## Штрихкоды

Принимаются EAN-8, UPC-A (12 цифр) и EAN-13 с проверкой контрольной цифры;
UPC-A и он же в форме EAN-13 с ведущим 0 — один продукт.

**barcode-list.ru** (работает из России без VPN) — по коду отдаёт только название
(«ВМ Кефир 1% 0,950л»), без калорийности. `GET https://barcode-list.ru/barcode/RU/Поиск.htm?barcode=<код>`,
User-Agent `SmartEsp-food/0.1 (home assistant)`, таймаут 5 с на весь запрос.
Название принимается только из строки таблицы результатов с запрошенным кодом (лучший рейтинг; `<title>` — лишь для регистра букв). Страница без такой строки (блокировка, капча, другая вёрстка) — «не получилось найти», в кэш не попадает; кодировка —
из заголовка или `<meta>`, иначе UTF-8/Windows-1251. Запросы поштучные и не чаще раза в
10 секунд на весь коннектор (как разрешает их robots.txt): до 6 с запрос ждёт своей очереди,
если ждать дольше — «повтори через несколько секунд». Слот тратится и при сбое. Ответы, в том числе «не найдено», кэшируются на 30 дней
в общем для всех людей `<data>/barcode_names.json`; сбои и непонятные страницы не кэшируются.

Дальше название сопоставляется с таблицей и своими продуктами по словам и жирности
(«кефир 1%» → «кефир», а «кефир 2,5%» — нет). Молча ничего не пишется: ответ —
«Нашла: ВМ Кефир 1% 0,950л, упаковка 950 г. Похоже на «кефир» — 41 ккал на 100 г. Записать?»;
подтвердив, модель повторяет `food_log` с названием продукта и тем же штрихкодом (название
берётся из кэша; пишется именно предложенный продукт, без дневника; вес упаковки из названия становится порцией по умолчанию, если ≤ 1 кг).
Не похоже ни на что — «Нашла: …. Калорийности не знаю — скажи, сколько ккал на 100 г»,
потом `product_add` со штрихкодом.

**Open Food Facts** по умолчанию выключен (из России без VPN не открывается). Включается
переменной окружения `FOOD_OFF=1`: тогда он спрашивается после своей базы и до barcode-list.ru.
Запрос: `GET https://world.openfoodfacts.org/api/v2/product/<код>`, найденное кэшируется
в `products.json`.

Нет сети — честный ответ, поиск по названию работает. Это единственные обращения
коннектора в сеть.

## Встроенная таблица

`src/food_mcp/foods.tsv` — около 190 частых продуктов на 100 г (ккал, белки, жиры,
углеводы, вес штуки, синонимы). Значения **приблизительные**: основной источник —
USDA FoodData Central (общественное достояние); русские блюда (борщ, пельмени,
сырники…) и молочные продукты с российской жирностью — средние значения по
типичному рецепту и этикетке. Правится как обычный текстовый файл.

## Данные

Папка из переменной `SMARTESP_CONNECTOR_DATA` (без неё коннектор не запускается).
Данные раздельно по человеку из `_meta.person` вызова; нет человека — общая папка `home`.

```
<data>/<person>/products.json          своя база и кэш Open Food Facts
<data>/barcode_names.json              общий кэш названий barcode-list.ru (30 дней)
<data>/<person>/diary/YYYY-MM.jsonl    дневник: запись — строка JSON (и что сказал человек)
<data>/<person>/pending.json           последний вопрос «Уточни: …» (живёт 15 минут)
```

Запись атомарная (временный файл + rename).

## Запуск и проверка

```
SMARTESP_CONNECTOR_DATA=~/SmartEsp/connectors/food uv run food-mcp
uv run pytest -q && uv run ruff check && uv run ruff format --check && uv run pyright
FOOD_LIVE_OFF=1 uv run pytest -q -k live   # один тест с настоящим Open Food Facts
FOOD_LIVE_BARCODES=1 uv run pytest -q -k live_barcode   # один тест с настоящим barcode-list.ru
```
