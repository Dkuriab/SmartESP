# timers-mcp — таймеры и напоминания

MCP-коннектор SmartESP: таймеры с именами и напоминания на время. Когда таймер
или напоминание срабатывает, коннектор просит ядро сказать это вслух
(уведомление `announce`). Работает без сети, по stdio.

## Инструменты

| Инструмент | Что делает | Пример ответа |
|---|---|---|
| `timer_start(minutes, name="")` | Ставит таймер на `minutes` минут (можно дробное). Имя по умолчанию — «таймер»; повтор имени получает номер: «таймер 2», «картошка 2». | «Таймер «картошка» на 20 минут.» |
| `reminder_at(time, text)` | Напоминание. `time` — «ЧЧ:ММ» (сегодня, а если уже прошло — завтра) или дата-время ISO (`2026-11-20T09:00`). Местное время Mac. | «Напомню завтра в 07:00: зарядка.» |
| `timers()` | Что идёт и сколько осталось. | «картошка — 12 минут 30 секунд; напоминание «позвонить маме» — в 18:30.» |
| `timer_cancel(name)` | Отменяет по имени таймера или тексту напоминания, без учёта регистра; «все» — отменить все. | «Таймер «картошка» отменён.» |

Таймеры и напоминания у каждого человека свои: человек приходит в `_meta.person`
вызова; без него — общие «дом».

## Срабатывание

Коннектор шлёт MCP-уведомление журнала `notifications/message` с
`logger = "smartesp"` и `data = {"type": "announce", "text": ..., "person": ...}`:

- «Таймер «картошка»: время вышло.» (таймер без имени — «Таймер: время вышло.»);
- «Напоминание: позвонить маме.»;
- сработавшее, пока коннектор не работал, объявляется один раз при старте:
  «Пропущен таймер «картошка» (сработал в 14:20).»,
  «Пропущено напоминание «позвонить маме» (сработало в 14:30).»

Уведомление уходит и вне вызова инструмента — по постоянному каналу соединения
(stdio). Сессию последнего подключения коннектор запоминает в прослойке сервера;
пока клиента нет, объявления копятся и уходят при подключении. Ядру лучше
подключаться рукопожатием (`Client(..., mode="legacy")`): в протоколе 2026-07-28
уведомления журнала вне запроса формально не предусмотрены (SDK их доставляет,
но это не гарантировано спецификацией).

## «В работе»

Каждая идущая запись — задача «В работе» ядра: уведомление
`data = {"type": "task", "id", "title", "status", "eta", "person"}`. `id` постоянен
(вид, человек, имя и время срабатывания); `title` — «Таймер «картошка»» или
«Напоминание: позвонить маме»; `eta` — время срабатывания (ISO с поясом).
Поставили — `running`, сработала — `done`, отменили — `cancelled`. При запуске
коннектор сообщает все идущие записи заново (ядро после перезапуска коннектора
отменяет его прежние задачи).

## Данные

Папка — из переменной `SMARTESP_CONNECTOR_DATA` (без неё коннектор не
запускается и пишет, чего не хватает). Файл на человека:
`<data>/<person>/timers.json` (`home` — общие), JSON со списком записей
(`kind`, `name`, `due` — ISO с часовым поясом, `person`). Запись атомарная:
временный файл + rename.

## Запуск и проверки

```
uv sync
SMARTESP_CONNECTOR_DATA=/tmp/timers uv run timers-mcp   # stdio-сервер
uv run pytest -q
uv run ruff check && uv run ruff format --check
uv run pyright
```

Тесты идут через клиент-сессию SDK в памяти с поддельными часами (без ожидания
реального времени).
