# Веб-интерфейс SmartESP — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** веб-интерфейс в `ui/`, первая версия по утверждённому наброску.

- **Смотреть:**
  - схема «колонки → обработчики → диспетчер → голос» с подсветкой пути;
  - живая лента ходов;
  - состояние ядра, Ollama и колонок.
- **Менять:**
  - имена колонок;
  - модель и промпт диспетчера;
  - обработчики вкл/выкл;
  - голос («Скачать», «Прослушать», «Выбрать»).
- **Перезапуск ядра**, когда изменение его требует.

Ядро раздаёт собранный `ui/dist` на `/`.

**Architecture:**
- Одностраничное приложение на React. Ходит в ядро только через `/api/v1` и
  `WS /api/v1/events`.
- Типы клиента генерируются из OpenAPI ядра
  (`python -m smartesp --openapi`).
- Состояние — один чистый редьюсер плюс тонкий слой эффектов (HTTP, WS,
  переподключение). Компоненты только показывают состояние и вызывают
  действия.
- Схема строится чистой функцией из состояния: узлы, связи, подсветка.

**Tech Stack:**
- TypeScript (strict), React, Vite, `@xyflow/react`;
- `openapi-typescript` и `openapi-fetch`;
- Vitest и Testing Library;
- ESLint.

Версии — последние стабильные на момент установки (`npm view <pkg> version`),
закреплённые точно (`--save-exact`), плюс `package-lock.json` в git.

**Spec:** `docs/superpowers/specs/2026-11-18-app-voices-design.md`:
- раздел 5.5 «Интерфейс»;
- раздел 9 основного дизайна `2026-11-18-core-design.md`.

Набросок: `docs/superpowers/specs/2026-11-18-app-mockup.html`. Ресурсы и
события API — в `docs/superpowers/plans/2026-11-18-core-control.md` («Имена

## Global Constraints

- Весь код — в `ui/`. У папки свой `ui/CLAUDE.md` (задача 1).
- Корневые правила (`CLAUDE.md`):
  - имена по-английски, комментарии по-русски;
  - коммиты по-английски и заканчиваются строкой
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - пушим сразу в `main`.
- Файл ≤ 300 строк, компонент или функция ≤ 50 строк. Компонент — один файл,
  папка на раздел интерфейса.
- В интерфейс не попадает ничего, кроме `/api/v1` и `/api/v1/events`. Никаких
  других путей к ядру.
- Все тексты интерфейса — по-русски.
- Тема только тёмная, цвета из наброска:
  - `--canvas:#141416`, `--dot:#2a2a2e`;
  - `--panel:#1c1c1f`, `--panel2:#232327`, `--line:#2f2f34`;
  - `--text:#f2f2f4`, `--muted:#8e8e93`, `--faint:#5c5c61`;
  - `--accent:#3d8bfd`, `--accent-bg:#1d3355`;
  - `--green:#32d74b`, `--orange:#ff9f0a`, `--purple:#bf5af2`.

  Шрифт — системный (`-apple-system`).
- Лента хранит не больше **100** ходов.
- WebSocket переподключается сам через 1, 2, 5, 5, … с. После
  переподключения интерфейс заново запрашивает `status`, `config`, `voices`
  и `turns`.
- Токен:
  - берётся из `?token=` при открытии;
  - кладётся в `localStorage` (`smartesp.token`) и убирается из адреса
    (`history.replaceState`);
  - при 401 или 4401 показывается экран «Введите токен» с полем ввода.
- Доступ к `localStorage` обёрнут в `try/catch`: без него интерфейс тоже
  работает, просто токен не запоминается.
- Перед каждым коммитом из `ui/`: `npm run typecheck`, `npm run lint`,
  `npm test -- --run`, `npm run build` — без ошибок и предупреждений.

## Review Focus

1. **Ядро недоступно или перезапускается.** Интерфейс не падает и не пустеет:
   показывает «Нет связи с ядром», данные остаются последними известными, а
   когда связь вернулась, всё обновляется само. Тест — задачи 2 и 3.
2. **Событие пришло раньше, чем загрузились данные, или пришло дважды.**
   Например, `turn_finished` до первого `GET /turns` или тот же ход ещё раз
   после переподключения. В ленте нет дублей (ключ — `turn_id`). Тест —
   задача 3.
3. **Медленное применение.** Скачивание Vosk на 900 МБ или прогрев модели до
   120 с. Кнопки не зависают. Видно «применяется…» и ход скачивания, итог —
   по `change_applied` и `voice_ready`. Повторы `voice_ready ok=false` при
   ретраях не сыпят уведомлениями: показывается состояние, а не тост на
   каждый повтор. Тест — задачи 3 и 6.
4. **Колонка без имени** (MAC вместо имени), **колонка из настроек, ни разу
   не подключавшаяся**, **ноль колонок**. Схема и списки выглядят осмысленно.
   Тест — задача 5.
5. **Очень длинный вопрос или ответ, промпт на несколько экранов.** Лента и
   панели не разъезжаются: текст переносится или обрезается с многоточием,
   а полный текст виден в карточке хода. Тест — задачи 4 и 6.

### Task 3: Состояние — редьюсер, действия, эффекты

**Files:**
- Create: `ui/src/state/model.ts` (типы состояния), `ui/src/state/reducer.ts`,
  `ui/src/state/actions.ts`, `ui/src/state/useCore.ts`
- Test: `ui/src/state/reducer.test.ts`, `ui/src/state/actions.test.ts`

**Interfaces:**
- Produces:
  - `type CoreState`:
    - `connection: "connecting" | "online" | "offline" | "unauthorized"`;
    - `status`, `config`, `voices`, `models` — каждое `| null`;
    - `turns: Turn[]` — новые первыми, не больше 100;
    - `selected: {kind: "device" | "stage" | "dispatcher" | "voice", id: string} | null`;
    - `selectedTurnId: number | string | null`;
    - `downloads: Record<"kind/voice", {done: number, total: number | null}>`;
    - `pending: Record<number, string>` — `change_id` → описание;
    - `notice: {text: string, tone: "ok" | "error"} | null`.
  - `reduce(state, action): CoreState` — чистая функция. Действия:
    - `loaded` (любой из ресурсов);
    - `event` (`CoreEvent`);
    - `connection`;
    - `select`, `selectTurn`;
    - `changeSent` (`change_id`, описание);
    - `dismissNotice`.
  - Правила событий:
    - `turn_finished` — в начало ленты, без дублей по `turn_id`, обрезка до
      100;
    - `device_connected` / `device_disconnected` — обновляют
      `status.devices`, добавляют неизвестную колонку;
    - `voice_download` — пишет `downloads`;
    - `voice_ready`:
      - убирает запись из `downloads`;
      - при `ok` и при первом неуспехе даёт `notice`;
      - повторный неуспех для того же голоса `notice` не даёт;
    - `change_applied` — убирает из `pending`, даёт `notice` («Применено» или
      текст ошибки);
    - `core_state` — `status.state`.
  - `useCore()` — хук. Читает токен, загружает ресурсы, подключает события,
    после `change_applied`, `voice_ready` и переподключения заново
    запрашивает `config`, `status`, `voices`. Отдаёт `[state, actions]`.
  - `actions`:
    - `patchConfig(patch, description)`;
    - `downloadVoice(kind, voice)`;
    - `previewVoice(kind, voice, style): Promise<Blob>`;
    - `selectVoice(kind, voice)` — это `patchConfig({tts:{kind, voice}})`;
    - `renameDevice(id, name)`;
    - `setStages(list)`;
    - `setDispatcher({model?, system_prompt?})` — меняет запись с
      `entry: true` в списке `executors` из `config.effective` и шлёт весь
      список;
    - `restart()`;
    - `setToken(token)`.

    Ответ 422 или 503 становится `notice` с текстом ошибки, без исключения.

  - 105 ходов → 100;
  - `connection offline` сохраняет данные.

  - `setDispatcher({model:"x"})` шлёт `executors` целиком, с
