# Ядро, этап 1 — голосовой цикл: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Колонка задаёт вопрос голосом и получает голосовой ответ от модели Ollama; при нескольких колонках отвечает одна.

**Architecture:** Прошивка переходит на протокол v2 (`device_id`, `level`, `cancel_turn`, `announce`, продление по `thinking`). На Mac — ядро `core/` (Python, asyncio): модули за договорами из `contracts/`, связка в `main.py`, поток хода в `conversation`. Колонки подключаются к `ws://<mac>:8765/device`, как к тестовому серверу.

**Tech Stack:** Прошивка — C++ / Arduino (esp32 3.3.12), host-тесты clang++. Ядро — Python 3.12 (uv), FastAPI 0.163.2 + uvicorn 0.54.0, pydantic 2.14.3, PyYAML 6.0.3, ollama 0.6.3, mlx-whisper 0.4.3, piper-tts 1.8.0, soxr 1.1.0, numpy 2.5.5; тесты pytest 9.2.0 + pytest-asyncio 1.5.0 + httpx 0.28.1; ruff 0.17.5, pyright 1.1.414.

**Spec:** `docs/superpowers/specs/2026-11-18-core-design.md` (этап 1 — раздел 8, протокол — раздел 7, правила — 6.1). Прошивка: `docs/superpowers/specs/2026-11-15-firmware-design.md`.

## Global Constraints

- Правила `core/` (дизайн 6.1): модуль — пакет `core/smartesp/<module>/`, публичное — только экспорт `__init__.py`; **модули не импортируют друг друга**, общие типы и протоколы — только `smartesp/contracts/` (без логики); связка — `smartesp/main.py` без своей логики; сменные реализации регистрируются по имени одной строкой в `main.py`.
- Размеры: файл ≤ 300 строк, функция ≤ 50 строк, сложность ≤ 10 (`ruff` C901); `pyright` strict для `contracts/`.
- Всё async; тяжёлое (STT, TTS) — `asyncio.to_thread`.
- Каждый модуль тестируется на подделках из `core/fakes/`, без моделей и железа. Тесты с настоящими моделями — маркер `models`, по умолчанию пропускаются.
- Имена на английском, комментарии и docstring'и — на русском. `ruff format` + `ruff check`.
- Звук: PCM 16 кГц, s16le, моно — везде внутри ядра и на проводе.
- Порт ядра — `8765`, путь колонок — `/device` (как тестовый сервер; `secrets.h` не меняется).
- Папка данных `~/SmartEsp/` (переменная `SMARTESP_HOME` меняет путь): `config.yaml`, `voices/`, `logs/`.
- Прошивка — по `CLAUDE.md` (модули не знают друг друга, `.ino` только связка, без блокировок).
- Git: ветка + PR на задачу или группу (указано в задаче), коммиты на английском, описание PR на русском (Что / Зачем / Как проверить).

## Review Focus

1. **Колонка пропала посреди ответа** (Wi-Fi, перезагрузка) → отправка звука прекращается без исключений в цикле хаба, ход отменяется; после переподключения с тем же `device_id` старая сессия заменяется новой. Тест — задача 6.
2. **Whisper на тишине/шуме выдаёт мусор** (пусто, «Продолжение следует…», «Субтитры …») → модель не вызывается, колонке уходит пустой ответ (`reply_start` + `reply_end`), чтобы она не ждала 15 с. Тест — задача 10.
3. **Ollama не запущена или модели нет** → колонке `tone error` и пустой ответ, в журнале понятная причина; цикл ядра живёт дальше. Тест — задача 10.
4. **Перебивание словом во время ответа** (`barge_in`) → генерация и отправка звука по старому ходу прекращаются; новый ход обрабатывается нормально. Тест — задача 10.
5. **Очень длинный ответ модели** → звук уходит не дальше чем на 10 с впереди воспроизведения (очередь ESP — 30 с, без переполнения). Тест — задача 6.
