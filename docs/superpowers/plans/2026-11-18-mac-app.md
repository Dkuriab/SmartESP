# Mac-приложение SmartESP — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** приложение `SmartEsp.app` для Mac.
- Запускает ядро дочерним процессом.
- Значок в строке меню виден всё время, пока работает ядро.
- Окно показывает веб-интерфейс ядра.
- Если закрыть окно, ядро продолжает работать. «Выйти» честно останавливает
  ядро.
- Если приложение упало, ядро завершается само (`--parent-watch`).
- Есть пункт «Запускать при входе».

**Architecture:**
- Пакет SwiftPM в `app/`. Две цели:
  - **`SmartEspKit`** — библиотека с логикой, проверяется тестами:
    - поиск `uv`, путь к репозиторию и папке данных;
    - чтение `run/core.json` и токена;
    - опрос `/api/v1/status`;
    - надзор за процессом ядра (состояния, перезапуски, остановка).
  - **`SmartEsp`** — тонкая обёртка на AppKit:
    - значок в строке меню и меню;
    - окно с WKWebView;
    - автозапуск;
    - выход.
- Процессы, файлы и HTTP скрыты за протоколами, поэтому логику можно
  проверить на подделках.
- `.app` собирает скрипт `app/build.sh`: `swift build -c release`, затем
  сборка пакета `.app`, `Info.plist` с путём к репозиторию и подпись ad-hoc.

**Tech Stack:**
- Swift 6.1 (Command Line Tools, без Xcode), SwiftPM;
- AppKit, WebKit (WKWebView);
- ServiceManagement (`SMAppService`);
- Foundation (`Process`, `URLSession`);
- тесты — `swift test`: XCTest, если доступен в CLT, иначе `swift-testing`
  (`import Testing`). Проверить в задаче 1.

**Spec:** `docs/superpowers/specs/2026-11-18-app-voices-design.md`, разделы 5.7
и 5.6, решения в разделе 8. Ядро:
- `core/README.md` — «Приложение и API», «Остановка и перезапуск»;
- флаг `--parent-watch`;
- `run/core.json` `{port, pid, started_at}`;
- `<data>/token`;
- `POST /api/v1/restart`;
- запуск только из папки `core/`: `uv run python -m smartesp`.

## Global Constraints

- Весь код — в `app/`. У папки свой `app/CLAUDE.md` (задача 1).
- Корневые правила:
  - имена по-английски, комментарии по-русски;
  - коммиты по-английски и заканчиваются строкой
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - пушим сразу в `main`.
- Swift: `UpperCamelCase` — типы, `lowerCamelCase` — остальное. Файл
  ≤ 300 строк, функция ≤ 50 строк. Логика живёт в `SmartEspKit`. В цели
  `SmartEsp` только связка с AppKit и WebKit.
- Минимальная macOS — 14. На этом Mac 15.3, Apple Silicon.
- Папка данных: `SMARTESP_HOME`, иначе `~/SmartEsp`.
- Ядро запускается так:
  - команда — `<uv> run python -m smartesp --parent-watch`;
  - `cwd` — `<repo>/core`;
  - stdin — открытая труба, которую приложение держит до выхода;
  - stdout и stderr — в `/dev/null`: ядро само пишет `logs/core.log`;
  - окружение — как у приложения, плюс `SMARTESP_HOME`, если задана.
- `uv` ищется по порядку:
  1. `~/.local/bin/uv`;
  2. `/opt/homebrew/bin/uv`;
  3. `/usr/local/bin/uv`;
  4. `PATH`.

  Не найден — состояние «ошибка: не найден uv» с подсказкой в меню.
- Путь к репозиторию — ключ `SmartEspRepoPath` в `Info.plist`. Его пишет
  `build.sh`, переопределяется переменной `SMARTESP_REPO`.
- Остановка ядра:
  1. SIGTERM;
  2. ждать до **15 с**;
  3. SIGKILL.
- Перезапуски после падения — не больше **3 за 60 с**, дальше состояние
  «ошибка» до кнопки «Перезапустить ядро».
- Опрос — раз в **1 с**: `run/core.json`, затем `GET /api/v1/status` с
  токеном.
- Ядро уже запущено не приложением (живой `pid` в `run/core.json`, `status`
  отвечает):
  - приложение подключается к нему, в меню «ядро запущено не из
    приложения»;
  - «Выйти» его не останавливает;
  - «Перезапустить ядро» шлёт `POST /api/v1/restart`.
- Окно — `http://127.0.0.1:<port>/?token=<token>` в WKWebView с постоянным
  хранилищем данных. Пока ядро не отвечает, вместо страницы заглушка «Ядро
  запускается…».
- Закрытое окно прячет значок из Dock (`.accessory`). Открытое окно
  возвращает его (`.regular`).
- **«Запускать при входе»:**
  - переключатель в меню, состояние — из `SMAppService.mainApp.status`;
  - по умолчанию включается при первом запуске, но **только если
    приложение лежит в `/Applications`** — чтобы проверочные сборки не
    прописывались в автозапуск;
  - если `SMAppService` не работает с ad-hoc подписью — LaunchAgent
    `~/Library/LaunchAgents/com.smartesp.app.plist` с
    `open -a /Applications/SmartEsp.app`.
- Тексты меню и окна — по-русски.
- Перед каждым коммитом из `app/`: `swift build` и `swift test` без ошибок;
  с задачи 4 — ещё `./build.sh`.

## Review Focus

1. **«Выйти», пока ядро прогревается или скачивает голос.** Выход всё равно
   завершается не дольше чем за 15 с, ядро не остаётся жить. Тест — задача 2.
2. **Ядро падает сразу при старте**: занят порт, неверные настройки,
   неизвестный вид. Не бесконечный цикл перезапусков: после 3 попыток —
   «ошибка» с последней строкой журнала. Тест — задача 2.
3. **Порт 8765 занят чужим процессом, а не ядром** (`core.json` нет или
   `pid` мёртв). Не «подключение» к чужому, а понятная ошибка. Тест —
   задача 2.
4. **Токена ещё нет** (первый запуск, ядро создаёт его при старте).
   Приложение дожидается файла и не открывает страницу без токена. Тест —
   задача 2.
5. **Приложение запущено второй раз.** Второй экземпляр не запускает второе
   ядро: показывает окно первого и выходит. Тест — задача 3, руками.

### Task 2: Надзор за ядром (`SmartEspKit`)

**Files:**
- Create:
  - `app/Sources/SmartEspKit/CoreProcess.swift` — протокол запуска и
    реальная реализация на `Process`;
  - `RunFile.swift`;
  - `StatusProbe.swift` — `URLSession` → `GET /api/v1/status`;
  - `CoreSupervisor.swift`.
- Test: `app/Tests/SmartEspKitTests/CoreSupervisorTests.swift`,
  `RunFileTests.swift`

**Interfaces:**
- Produces:
  - `struct RunInfo: Decodable { port: Int; pid: Int32; started_at: Double }`;
  - `RunFile.read(url) -> RunInfo?` — битый или пустой файл даёт `nil`.
  - `protocol CoreLaunching { func launch(uv: URL, cwd: URL, env: [String:String]) throws -> CoreHandle }`
    и `protocol CoreHandle { var pid: Int32 { get }; var isRunning: Bool { get }; func terminate(); func kill(); func onExit(_ cb: @escaping (Int32) -> Void) }`.
    Настоящая реализация: `Process`, stdin — `Pipe()`, держится открытой;
    `terminate` — SIGTERM.
  - `protocol StatusProbing { func status(port: Int, token: String) async -> ProbeResult }`,
    где `enum ProbeResult { case ok(state: String, devicesOnline: Int, devicesTotal: Int, ollama: Bool), unauthorized, unreachable }`.
  - `enum CoreState: Equatable`:
    - `stopped`, `starting`;
    - `running(port: Int, phase: String, devices: (Int, Int), ollama: Bool)` —
      `phase` = `warming` / `ready` / `stopping`;
    - `external(port: Int, …)`;
    - `stopping`;
    - `failed(String)`.
  - `@MainActor final class CoreSupervisor`:
    - конструктор: `paths`, `launcher`, `probe`, `clock`, `fileExists`,
      `pidAlive: (Int32) -> Bool`;
    - `var state: CoreState { get }`;
    - `var onChange: ((CoreState) -> Void)?`;
    - `func start()`, `func restart() async`, `func stop() async`;
    - `var token: String? { get }`, `var port: Int? { get }`.
  - Правила:
    - `start()`:
      - есть `core.json` с живым `pid` и `status` отвечает → `external`;
      - иначе запуск;
      - `core.json` есть, но `pid` мёртв, а порт отвечает 401 или
        недоступен → запуск. Если ядро потом упадёт с «address already in
        use» в последних строках журнала, будет `failed("Порт <p> занят
        другой программой")`.
    - Опрос раз в 1 с: файл запуска → порт, токен из файла → `status`.
      Токена нет → остаётся `starting`.
    - Ядро вышло неожиданно → перезапуск с ограничением 3 за 60 с, дальше
      `failed(последняя строка журнала)`.
    - `stop()`:
      - для `external` ничего не делает;
      - иначе `terminate`, ждать до 15 с, затем `kill`, потом `stopped`.
    - `restart()`:
      - для `external` — `POST /api/v1/restart`;
      - для своего — `POST /api/v1/restart` (pid сохраняется, ядро
        перезапускает себя само);
      - не отвечает → `stop()` и `start()`.

- [ ] **Step 1: Тесты** на подделках `CoreLaunching` и `StatusProbing` и
  поддельных часах:
  - старт → `starting` → (файл запуска и токен появились,
    `status=warming`) `running(phase:"warming")` → `ready`;
  - токена нет → `starting`, `status` не вызывается;
  - живое чужое ядро → `external`, `launch` не вызывался, `stop()` не
    шлёт сигналов;
  - падение 3 раза за 60 с → `failed` с последней строкой журнала (журнал
    — временный файл); 4-го запуска нет;
  - `stop()`: обработчик не выходит → через 15 с (поддельные часы) `kill`;
    выходит сразу → без `kill`;
  - `stop()` во время `starting` (прогрев) → то же правило 15 с
    (Review Focus 1);
  - порт занят чужим процессом (`pid` мёртв, ядро падает с «address
    already in use») → `failed("Порт 8765 занят другой программой")`;
  - `RunFile`: битый JSON → `nil`.
- [ ] **Step 2: FAIL. Step 3: Реализовать.** Время — через инжектируемые
  часы и `sleep`, чтобы тесты шли быстро. **Step 4: PASS.**
