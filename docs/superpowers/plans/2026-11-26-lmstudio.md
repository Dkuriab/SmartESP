# LM Studio рядом с Ollama — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** третий вид исполнителя `lmstudio`: модель локального сервера LM Studio (OpenAI-совместимый API),
свой раздел настроек с адресом и ключом, список моделей для выбора, понятные ошибки.

**Architecture:** общая часть облачного исполнителя (формат OpenAI, поток SSE, сборка вызовов
инструментов, повтор без рассуждения) выносится в базовый класс `OpenAIChatExecutor`; `CloudExecutor`
и новый `LmStudioExecutor` — его наследники с своими телом запроса и текстами ошибок. Список моделей —
`lmstudio_models.py` (REST API LM Studio с запасными путями). Связка: одна строка в `EXECUTOR_KINDS`,
приставка `@lmstudio/` в `model_key`, раздел `lmstudio` на лету, маршрут `GET /lmstudio/models`.

**Tech Stack:** Python 3.12, httpx (уже есть), pytest + `httpx.MockTransport`; UI — React + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-lmstudio-design.md` (ветка `docs/discovery-lmstudio-design`);
образец — `docs/superpowers/specs/2026-11-21-cloud-models-design.md`.

## Global Constraints

- Правила `core/CLAUDE.md`: файл ≤ 300 строк, функция ≤ 50, сложность ≤ 10, модули импортируют только
  `smartesp.contracts`, связка без логики, комментарии по-русски.
- Тесты не ходят в сеть и не трогают `~/SmartEsp`: только подделка сервера (`httpx.MockTransport`).
- Адрес по умолчанию `http://localhost:1234`; ключ необязателен; в `GET /config` непустой ключ — «•••».
- Работа `ollama` и `cloud` не меняется (их тесты проходят без правок поведения).
- CONFIG_VERSION не меняется: новый раздел с умолчаниями, переносить нечего.

## Решения на усмотрение исполнителя

- **Рассуждение:** `reasoning != off` → поле `reasoning_effort` (low/medium/high); `off` — поле не шлём.
  LM Studio отклонил поле (400 со словом reasoning) — один повтор без него (как у облака). Текст
  рассуждения в ответ не попадает: `reasoning_content` не читаем, блоки `<think>…</think>` в `content`
  вырезаются потоковым фильтром (когда в LM Studio выключено отделение рассуждения).
- **ttl:** `keep_alive` исполнителя («24h», «30m», «90s», «3600») → `ttl` в секундах в каждом запросе
  (LM Studio применяет его к модели, загруженной по запросу JIT); «-1», «0» и непонятное — `ttl` не шлём.
- **Прогрев:** крошечный запрос `chat/completions` (`max_tokens: 1`, без потока) — LM Studio загружает
  модель сам (JIT); отдельный load не используем, чтобы не создать второй экземпляр уже загруженной модели.
- **Возможности:** `@lmstudio/…` — «completion, tools» без запроса в Ollama (LM Studio даёт инструменты
  любой модели; родная поддержка показывается в списке пометкой).
- **Адрес через API:** меняется (http/https, одна строка). Смена адреса без нового ключа в той же правке
  сбрасывает ключ: токен API не может увести ключ на чужой сервер.

## Review Focus

- LM Studio не запущен (соединение отклонено) → ошибка «Сервер LM Studio не запущен по адресу …» и в ходе, и в списке моделей.
- Адрес введён с `/v1` или `/` в конце → работает так же, как без них.
- `/api/v1/models` нет (старый LM Studio, 404) → список берётся из `/api/v0/models`, затем `/v1/models`.
- Тег `<think>` разрезан между кусками потока → в речь не попадает ни рассуждение, ни обломки тега.
- Правка `lmstudio.api_key = «•••»` → ключ не меняется; смена адреса без ключа → ключ сброшен.
