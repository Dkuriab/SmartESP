# MCP-хаб и первые коннекторы — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** ядро запускает MCP-коннекторы и даёт модели их инструменты; три коннектора — `notes`, `calc`, `timers`.

**Architecture:** задачи 1–5 независимы и идут параллельно, каждая в своей ветке от `feature/mcp-hub` (там уже есть договор `contracts/tools.py`). Задача 6 (связка, настройки, API, интерфейс, живая проверка) — после плана речи по инициативе.

**Tech Stack:** Python 3.12, uv, `mcp==2.3.0` (FastMCP, stdio), pytest, ruff, pyright; ядро — asyncio.

**Spec:** `docs/superpowers/specs/2026-11-19-mcp-hub-design.md`

## Global Constraints

- `mcp==2.3.0` везде (ядро и коннекторы), остальные зависимости — `==`; новая зависимость — в `uv.lock` того же проекта.
- Коннектор: `connectors/<name>/` — свой uv-проект, Python 3.12, пакет `<name>_mcp/`, скрипт запуска `<name>-mcp` (stdio), README по-русски (что умеет, инструменты, данные, как запустить), тесты pytest через клиент-сессию SDK в памяти (без подпроцессов, где SDK позволяет).
- Данные коннектора — только в папке из `SMARTESP_CONNECTOR_DATA` (нет переменной — ошибка запуска с понятным текстом); тесты пишут во временную папку, никогда в `~/SmartEsp`. Запись атомарная (временный файл + rename). Сети нет.
- `_meta.person` вызова: строка или нет; нет — данные общие «дом» (`home`). Хранить по человеку: `<data>/<person>/...`.
- Описания инструментов и параметров — по-русски, коротко, с примером, когда полезно; ответы инструментов — короткий русский текст, пригодный для озвучки (без разметки).
- Правила кода ядра (`core/CLAUDE.md`) — и для коннекторов: файл ≤ 300 строк, функция ≤ 50, сложность ≤ 10 (ruff C901), pyright без ошибок, `ruff format`, имена английские, комментарии и docstring'и по-русски.
- Сообщение от коннектора ядру: MCP-уведомление журнала `notifications/message`, `logger = "smartesp"`, `data = {"type": "announce", "text": str, "person": str | None}`.
- Ветки и коммиты: работа в своей worktree-папке на своей ветке; сообщения коммитов английские, в конце `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; не пушить.

### Task 1: коннектор `notes` (ветка `mcp/notes`)

**Files:** `connectors/notes/` (pyproject, uv.lock, `notes_mcp/`, `tests/`, README).

Инструменты (имена — точно такие):
- `list_add(list: str, items: list[str])` — добавить пункты в именованный список (создаёт список). Ответ: «Добавила в «покупки»: молоко, хлеб.»
- `list_show(list: str)` — пункты списка по порядку; пустой/нет — «Список «покупки» пуст.»
- `list_remove(list: str, items: list[str])` — вычеркнуть (совпадение без регистра, «молоко» вычёркивает «молоко 2 л»; неоднозначно — не вычёркивать, вернуть варианты).
- `list_clear(list: str)`, `lists()` — какие списки есть.
- `note_add(text: str)` — заметка с датой; `notes_find(query: str)` — до 5 последних совпадений; `note_delete(query: str)` — удаляет единственное совпадение, иначе просит уточнить.

Хранение: `lists/<имя>.md` (пункт — строка `- `), `notes/YYYY-MM-DD.md` (заметка — абзац с временем). Имя списка нормализуется (регистр, «ё», пробелы) — «Покупки» и «покупки» — один список.

- [ ] Тесты сначала (каждый инструмент, нормализация имён, частичное совпадение, неоднозначность, `person` раздельно, атомарность — файл не портится при ошибке записи) → реализация → `uv run pytest`, `ruff`, `pyright` → коммит `feat(connectors): notes MCP — notes and named lists`.

### Task 2: коннектор `calc` (ветка `mcp/calc`)

**Files:** `connectors/calc/`.

Инструменты:
- `calculate(expression: str)` — `+ - * / ** % ( )`, десятичная запятая и точка, `sqrt round abs min max`; разбор через `ast` с белым списком (не `eval`), предел длины 200 и степени (без «9**9**9»). Ответ — число, до 4 значащих после запятой, без хвостовых нулей, запятая как в русском («50,5»). Деление на ноль, мусор — понятная ошибка.
- `convert(value: float, from_unit: str, to_unit: str, product: str = "")` — масса (мг, г, кг, фунт, унция), объём (мл, л, ч. л., ст. л., стакан 250 мл), температура (°C/°F); масса↔объём — только с `product` из таблицы плотностей (мука, сахар, соль, рис, гречка, молоко, вода, масло растительное, масло сливочное, мёд, крупа манная) — иначе честный отказ. Единицы принимаются в русских формах и сокращениях («грамм», «граммов», «г», «столовая ложка», «ст.л.»).
- `split(total: float, parts: int, unit: str = "")` — «500 г на 10 порций — по 50 г».

- [ ] Тесты (таблица случаев на каждый инструмент, включая опасные выражения) → реализация → проверки → коммит `feat(connectors): calc MCP — exact math and kitchen units`.

### Task 3: коннектор `timers` (ветка `mcp/timers`)

**Files:** `connectors/timers/`.

Инструменты:
- `timer_start(minutes: float, name: str = "")` — имя по умолчанию «таймер», повтор имени — «таймер 2». Ответ: «Таймер «картошка» на 20 минут.»
- `reminder_at(time: str, text: str)` — «ЧЧ:ММ» (сегодня, а если прошло — завтра) или ISO; местное время Mac.
- `timers()` — что идёт и сколько осталось словами («картошка — 12 минут 30 секунд»).
- `timer_cancel(name: str)` — без регистра; «все» — отменить все.

Срабатывание: уведомление `announce` (см. Global Constraints) с текстом «Таймер «картошка»: время вышло.» / «Напоминание: <текст>.». Состояние — `timers.json` (атомарно), переживает перезапуск; пропущенное за простой — одно уведомление «Пропущен таймер «…» (сработал в ЧЧ:ММ).» при старте. Уведомление отправляется и вне вызова инструмента: исполнитель проверяет, как в `mcp==2.3.0` послать `notifications/message` из фоновой задачи сервера (сессия последнего подключения); если SDK не даёт — DONE_WITH_CONCERNS с описанием.

- [ ] Тесты (часы — подделка, не `sleep` реального времени; срабатывание шлёт уведомление в клиентскую сессию в памяти; перезапуск с файлом; пропущенные; отмена) → реализация → проверки → коммит `feat(connectors): timers MCP — named timers and reminders with announce`.

### Task 4: хаб в ядре `smartesp/tools/` (ветка `mcp/hub`)

**Files:** `core/smartesp/tools/` (`__init__.py`, `hub.py`, при необходимости `connector.py`), `core/pyproject.toml` + `uv.lock` (`mcp==2.3.0`), `core/tests/tools/`, `core/CLAUDE.md` (модуль `tools/` есть).

**Interfaces (produces):**
- `ConnectorSpec(id: str, name: str, command: str, args: tuple[str, ...], env: Mapping[str, str], enabled: bool)` — dataclass модуля.
- `ConnectorState(id, name, state: Literal["starting","ready","failed","disabled"], tools: tuple[str, ...], error: str)`.
- `class McpHub` (реализует `contracts.ToolBox`): `__init__(data_dir: Path, *, on_announce: Callable[[str, str | None, str], None] | None = None, call_timeout_s: float = 15.0, restart_delays_s: tuple[float, ...] = (1.0, 5.0, 30.0, 300.0))`; `async start(specs: Sequence[ConnectorSpec]) -> None` (запускает все, не ждёт дольше 10 с каждого; упавший — `failed`, не исключение); `async apply(specs) -> None` (перезапускает только изменившиеся, останавливает убранные); `specs()`, `call(...)` — по договору; `states() -> list[ConnectorState]`; `async aclose() -> None`.
- Окружение подпроцесса: окружение ядра + `env` + `SMARTESP_CONNECTOR_DATA=<data_dir>/connectors/<id>` (создать папку).
- Совпадение имён инструментов — второму префикс `<id>_`, предупреждение в журнал.
- `on_announce(text, person, connector_id)` по уведомлению с `logger == "smartesp"` и `data.type == "announce"`; другие уведомления журнала → журнал ядра (уровень как у уведомления).

- [ ] Тесты: настоящий подпроцесс маленького тестового MCP-сервера (файл в `core/tests/tools/`, запускается `sys.executable`): инструменты видны; вызов; таймаут → `is_error`; сервер упал → `failed` и перезапуск по задержкам (малые задержки в тесте); `apply` перезапускает только изменённый; announce доходит до `on_announce`; совпадение имён; `aclose` не оставляет процессов. Затем реализация, `uv run pytest -q`, `ruff`, `pyright` → коммит `feat(core): MCP hub — connectors as stdio subprocesses`.

### Task 5: вызов инструментов в сети исполнителей (ветка `mcp/toolloop`)

**Files:** `core/smartesp/network/tool_loop.py` (новый; `network.py` уже 283 строки), `network/network.py`, `network/build.py` (параметр `toolbox`), `core/fakes/fake_toolbox.py`, `core/tests/network/test_tool_loop.py`.

**Interfaces:**
- Consumes: `contracts.ToolBox`, `ToolResult`, `ToolSpec`.
- `build_network(..., toolbox: ToolBox | None = None)` — участники с поддержкой инструментов получают `toolbox.specs()` вместе с `delegate` (снимок на момент сборки).
- Модель вызвала не `delegate`: `await toolbox.call(name, args, person=None)` → в сообщения участника добавить `ChatMessage("assistant", <сказанный до вызова текст>, tool_calls=(call,))` и `ChatMessage("tool", result.text, tool_name=name)` → снова `executor.run(messages, tools)`, куски идут дальше в тот же поток. Не больше 4 вызовов на ответ участника; 5-й → `ReplyPart("Не получилось выполнить действие.", failure=True)` и конец. Инструмент, которого нет в `specs()`, → результат-ошибка модели «Нет такого инструмента: X».
- `delegate` работает как прежде; цели передачи тоже могут вызывать инструменты.

- [ ] Тесты (поддельная модель, поддельный `ToolBox`): вызов → результат попал в сообщения → ответ после вызова звучит; текст до вызова звучит до него; два вызова подряд; предел 4; неизвестный инструмент; ошибка инструмента отдаётся модели; модель без поддержки инструментов не получает их; `delegate` и инструмент в одном ответе. Затем реализация, весь набор ядра, `ruff`, `pyright` → коммит `feat(core): executors call connector tools`.
