# SmartESP Firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Прошивка умной колонки на ESP32-S3: слово-активатор с эхоподавлением, потоковая связь с сервером по WebSocket, перебивание ответа.

**Architecture:** Независимые модули в `src/<module>/` (один класс, не подключают друг друга), общие типы в `src/common/Types.h`, вся связка в `SmartEsp.ino`. Звуковые модули работают в своих задачах FreeRTOS и отдают данные через неблокирующие `read`/`write`/`poll`. Чистая логика (`session`, разбор протокола) тестируется на ноутбуке.

**Tech Stack:** Arduino IDE / arduino-cli, ядро esp32 3.3.12, ESP-SR (AFE напрямую), WebSockets 2.7.2, ArduinoJson 7.4.3; тесты логики — clang++ C++17 на Mac; тестовый сервер — Python 3.9 + `websockets` 15.0.1.

**Spec:** `docs/superpowers/specs/2026-11-15-firmware-design.md` (далее «дизайн»). Рабочий образец звуковой части — `spikes/wakeword_aec/wakeword_aec.ino` в ветке `spike/wakeword-aec` (`git show spike/wakeword-aec:spikes/wakeword_aec/wakeword_aec.ino`).

## Global Constraints

- Правила `CLAUDE.md` обязательны: модуль = папка `src/<module>/` с одним классом; модули подключают только `src/common/Types.h`, не друг друга; пины/настройки — через `begin(...)`; никаких `delay()` и долгих ожиданий в модулях и в `loop()`; комментарии на русском, имена на английском; `PascalCase` / `camelCase` / `UPPER_SNAKE_CASE`.
- `src/common/Types.h` — только типы (enum, struct), без функций, переменных, `#include <Arduino.h>`; должен компилироваться на ноутбуке.
- Ядро **esp32 3.3.12**; FQBN: `esp32:esp32:esp32s3:PartitionScheme=esp_sr_16,FlashSize=16M,PSRAM=opi`.
- Звук везде: PCM 16 кГц, 16 бит со знаком, моно, little-endian.
- Пины: микрофон SCK 5 / WS 4 / SD 9; динамик BCLK 7 / LRC 6 / DIN 8.
- Микрофон: 32-битный отсчёт, левый слот, `>> 14` с ограничением до int16. Динамик: стерео 16 бит, оба канала одинаковые.
- AFE: формат `"MR"`, `AFE_TYPE_SR`, `AFE_MODE_LOW_COST`, без MultiNet; `vad_min_noise_ms = 500`; задержка образца 80 мс.
- `#include "ESP_SR.h"` обязателен в `voice_frontend` (иначе не прошиваются модели).
- `WiFi.setSleep(false)`.
- WebSocket: `ws://SERVER_HOST:SERVER_PORT/device`; ESP шлёт звук кадрами по 512 отсчётов (1024 байта).
- Таймауты сценария: нет речи 5000 мс, максимум вопроса 10000 мс, ожидание ответа 15000 мс.
- Очередь ответа 30 с; начало воспроизведения после 100 мс в очереди.
- Каждый PR — своя ветка от свежего `main` (если предыдущий PR ещё не смёржен — от его ветки), описание PR по шаблону `CLAUDE.md` с чек-листом проверки на плате.

## Review Focus

1. **`loop()` подвис на подключении к серверу/Wi-Fi** (сервер выключен, библиотека ждёт TCP) → устройство не падает, после подвисания слово снова ловится; переполнение буфера `audio_in` пишется в Serial, а не роняет прошивку. Проверка — Task 7, шаг проверки на плате.
2. **Ответ длиннее 30 с или сервер шлёт быстрее реального времени** → лишнее отбрасывается с предупреждением, без падения, остальное доигрывает. Проверка — Task 7 (флаг `--long` тестового сервера).
3. **Бинарный кусок нечётной длины от сервера** → отсчёты не сдвигаются (лишний байт переносится в следующий кусок). Проверка — Task 7 (флаг `--odd`).
4. **Мусорный/неизвестный JSON или без `turn`** → игнорируется, без падения. Проверка — host-тест `decode_rejects_garbage` в Task 6.
5. **Нет Wi-Fi / неверный пароль / сервер недоступен при старте** → прошивка стартует, на слово звучит тон ошибки. Проверка — Task 9, шаг проверки на плате.

### Task 2: `audio_out` — динамик

**Files:**
- Create: `src/audio_out/AudioOut.h`, `src/audio_out/AudioOut.cpp`
- Modify: `SmartEsp.ino`

**Interfaces:**
- Consumes: `Tone` из `Types.h`.
- Produces:

```cpp
struct AudioOutConfig { int bclkPin; int lrcPin; int dinPin; uint32_t refDelayMs = 80; uint32_t queueSeconds = 30; uint32_t prebufferMs = 100; };
class AudioOut {
 public:
  bool begin(const AudioOutConfig& config);
  size_t write(const int16_t* pcm, size_t samples);       // неблокирующе; вернёт сколько принято
  void playTone(Tone tone);                                // сразу, очередь ставится на паузу на время тона
  void stop();                                             // очистить очередь и тон
  void setVolume(float volume);                            // 0..1, по умолчанию 0.5
  bool isPlaying() const;                                  // очередь не пуста или звучит тон
  size_t readReference(int16_t* dst, size_t samples);      // потокобезопасно; нули, если тишина
};
```

- [ ] **Step 1: Реализовать `AudioOut`.** Своя задача FreeRTOS (как `playerTask` в образце): берёт из очереди или генератора тона кусками по 256 отсчётов, применяет громкость, пишет в I2S стерео, тот же кусок кладёт в буфер образца. Очередь — `StreamBuffer` в PSRAM на `queueSeconds` (`xStreamBufferCreateWithCaps(..., MALLOC_CAP_SPIRAM)`); переполнение → отбросить лишнее, `log_w` не чаще раза в секунду. Начинать играть очередь, когда в ней ≥ `prebufferMs`, или если новых данных нет 100 мс. При переходе тишина → звук положить в образец `refDelayMs` тишины. Тоны: Wake — 1000 Гц 150 мс; Error — 400 Гц 300 мс; Thinking — 600 Гц 80 мс, два раза с паузой 80 мс.

- [ ] **Step 2: Временная связка в `.ino`** — `AudioOut audioOut;` `begin({7, 6, 8})`, в `setup()` `audioOut.playTone(Tone::Wake)`.

- [ ] **Step 3: Сборка** — `tools/build.sh`, Expected: без предупреждений.
