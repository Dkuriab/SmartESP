# Третья волна: честность, настройки, интернет, отложенные задачи — дизайн

Дата: 2026-11-20. Список владельца после тестов. Помеченное «(моё)» — решения
контроллера, можно поправить.

## A. Модель-диспетчер и честность

- Замер моделей (владелец разрешил скачать «пободрее», но «не слишком долго
  отвечает»): Gemma (текущая), `qwen3:8b`, `gpt-oss:20b`, `qwen3:14b`. Один
  набор прямых проб Ollama с промптом и инструментами ядра: вызов инструмента
  при истории (вкл. «сессия началась с ответа без инструментов»), честность
  («включи свет»), передача сложных вопросов, болтовня без «нет доступа»,
  задержка первого текста и общая, русский язык. Победитель — лучший по
  честности при первом тексте ≤ 1,5 с (моё); владелец переключает в приложении.
- Проверка за моделью (страховка для любой модели): ответ входного исполнителя
  содержит утверждение о выполненном действии («поставила», «записала»,
  «включила», «узнала» …), а инструментов в ходе не было → ядро до озвучки
  первой фразы делает один повторный прогон с напоминанием «Ты не вызвал
  инструмент: вызови его или честно скажи, что не можешь». Нет инструмента и
  на второй раз → честная фраза. Проверяется только первое предложение до
  озвучки (не задерживает обычные ответы).

## B. Настройки коннекторов в приложении (город и т. п.)

- Коннектор объявляет свои настройки файлом `connectors/<id>/smartesp.json`:
  `settings: [{key, title, type: text|path|list|secret, hint}]`.
- Ядро позволяет менять через API **только объявленные ключи `env`** этого
  коннектора (остальное — по-прежнему только `config.yaml`); `secret` в ответах
  скрыт и не возвращается обратно.
- В панели коннектора — форма полей; сохранение перезапускает коннектор.
- Объявить: `weather` (WEATHER_PLACE), `claude_tasks` (CLAUDE_TASK_FOLDERS,
  CLAUDE_TASK_TOOLS), `food` (FOOD_OFF), `web` (если будут).

## C. Схема в приложении

- Схема на общем фоне и в стиле остального интерфейса.
- Узлы перетаскиваются; раскладка запоминается в браузере (по id узла), есть
  «Расставить заново».
- Баг: схема иногда пропадает, пока не переключишь вкладки — найти причину
  (вероятно, нулевой размер контейнера при первом рендере / fitView) и
  исправить.
- Живая подсветка: держится не меньше 1,2 с и плавно гаснет; подсветка
  «пути хода» показывается только для хода, выбранного в ленте (моё) — не
  «залипает» синим на прошлом инструменте.

## D. Время и шёпот

- Время не в разговоре: пометка `clock` уходит в системную часть одной строкой
  «Справочно, не упоминай без вопроса: сейчас четверг, 19 ноября 2026, 18:19»;
  проба: «который час» верно, в обычных ответах время не звучит (≤ 1 из 12).
- Шёпот: ответ шёпотом **выключен по умолчанию** (ни один голос не умеет
  настоящий шёпот — только тише). Распознавание шёпота — замер ложных
  срабатываний на обычной речи и попаданий на шёпоте (синтетика + пороги),
  исправить или выключить обработчик по умолчанию, если точность плохая.

## E. Интернет

- Коннектор `web`: `web_search(query)` — DuckDuckGo без ключа (владелец; Google
  не даёт бесплатного API, а разбор выдачи Google нарушает их правила и быстро
  упирается в капчу); `web_read(url)` — текст страницы (только http/https,
  не локальные адреса: 127.0.0.0/8, 10/8, 172.16/12, 192.168/16, .local —
  защита от доступа к домашней сети), до 8000 символов, без JavaScript.
  Ответы — коротко, со ссылкой на источник. Предел частоты запросов.

## F. Отложенные задачи и мягкие прерывания

- Реестр «В работе» в ядре: запоздавшие ответы моделей, задачи коннекторов
  (Клод, таймеры) — коннекторы сообщают через уведомление
  `{"type": "task", "id", "title", "eta", "status"}` (общий механизм, как
  `announce`). API `GET /tasks` + события; в приложении — панель «В работе»
  (что, с какой колонки/человека, когда ожидается).
- Приоритет: пока все отложенные результаты — высокий (владелец).
- Мягкое прерывание: результат приходит, а колонка говорит ответ → ядро
  перестаёт подавать новые предложения текущего ответа, колонка договаривает
  уже отправленное (сейчас ≤ 1 предложение вперёд), затем звучит «Кстати,
  готово: …», затем «Вернёмся к тому, о чём говорили?» и колонка слушает;
  «да» → Кузя продолжает с недосказанного (непроизнесённый остаток ответа
  сохраняется для этого хода).
- Колонка сообщает ядру, что доиграла кусок (новое событие протокола
  `played{turn, bytes}` раз в ~0,5 с) — чтобы ядро знало, где сейчас речь
  (правка прошивки, протокол 3 совместимо: старые колонки — по оценке времени).

Как сделано (решение по протоколу): срезать уже отправленный колонке звук на
границе предложения протокол не умеет (`cancel_turn`/barge-in режут сразу, а
`played` приходит раз в 0,5 с — точно попасть в границу нельзя), поэтому прошивку
не меняли. Вместо этого ядро отдаёт колонке только целые предложения и не больше
3 с звука впереди услышанного (по `played`, без него — по оценке темпа); после
просьбы уступить новых предложений не шлёт, сразу `reply_end` — колонка
договаривает текущее предложение (и не больше ~3 с следующего), `playback_done`,
затем объявление. Прерывается только ответ, начатый раньше результата; человек
говорит или модель думает — объявление ждёт конца хода. Остаток — неотправленные
предложения и то, что модель допишет в фоне, — 5 минут ждёт «да».
