# Движок слова пробуждения microWakeWord — короткий дизайн

Дата: 2026-11-19. Решение владельца в разговоре.

## Зачем

Владелец хочет своё слово «Кузя» (бэклог). Сейчас колонка слушает «Hi, ESP» через
WakeNet от Espressif: свои слова под него не обучить. Владелец: подключить движок
сейчас, с готовой русской моделью, чтобы потом просто заменить её на нашу
обученную «Кузю». Прошить колонку один раз вместе с речью по инициативе.

## Замер готовых моделей (синтетика: 11 голосов Silero/Piper/Vosk, 5 искажений, 27 мин речи без слова)

| Модель | На ESP32 | Узнаёт (чистая) | Ложные |
|---|---|---|---|
| «Kuza» (splastunov, GitHub) | нет: внутри голова openWakeWord | 62% | ~7/ч |
| «Миранда» (archer-developer) | да | 98% | 2% фраз при пороге 0,9 |
| «Алиса» (olegchumakov) | да | 73% | 1% фраз; путается с Яндексом |
| «Скайнет» (olegchumakov) | да | 36% | есть |
| «Окей, Набу» (ESPHome) | да | 86% | 0 |

Готовой «Кузи» для ESP32 нет. Владелец выбрал **«Миранду»** на время.

## Подходы

1. **microWakeWord на колонке** (выбрано): маленькая потоковая модель TFLite
   Micro (int8), работает на ESP32-S3 (так делает Home Assistant Voice). Свою
   «Кузю» обучаем тем же конвейером microWakeWord и меняем только файл модели.
2. openWakeWord на Mac (колонка шлёт звук непрерывно): без Mac колонка глухая,
   микрофон всё время в сети. Отклонено.
3. Оставить WakeNet: своё слово не обучить. Отклонено.

## Как устроено

- **AFE остаётся** (эхо- и шумоподавление, VAD), WakeNet в нём выключается.
- **`voice_frontend`** отдаёт очищенный звук постоянно (не только при захвате) —
  отдельным потоком для слова пробуждения; громкость слова (`level`) он
  по-прежнему считает по последней секунде.
- **Новый модуль `wake_word/`** (`WakeWord`): `begin(model, cutoff, window)`,
  `feed(pcm, samples)`, `poll()` — «слово услышано». Внутри:
  - признаки — микрофронтенд TFLite (`tensorflow/lite/experimental/microfrontend`,
    Apache 2.0), настройки microWakeWord: окно 30 мс, шаг 10 мс, 40 каналов,
    125–7500 Гц, шумоподавление и PCAN, лог-шкала (как в `pymicro-features`);
  - признаки × 0,0390625 → квантование по параметрам входа модели;
  - модель — потоковая, входной кадр [1, 3, 40], вызов каждые 3 шага;
  - вероятность усредняется по `sliding_window_size` кадрам, срабатывание выше
    порога, затем пауза 1 с (не сработать дважды на одно слово).
- **Модель** — массив байтов в прошивке (`src/wake_word/ModelData.cpp`,
  создаётся `tools/embed_model.py` из `.tflite` + `.json`). Порог — **0,9**
  (у автора 0,5: слишком много ложных). Загрузка модели по сети — бэклог.
- **TFLite Micro** — из ядра ESP32 для Arduino (`esp-tflite-micro`), если он
  там есть; иначе — библиотека с точной версией в README.
- **`SmartEsp.ino`** — связка: звук из `voice_frontend` → `wake_word` →
  событие `WakeWord` с громкостью → `session`. Остальное не меняется.

## Проверка

- Host-тест на ноутбуке: признаки фронтенда на записи совпадают с
  `pymicro-features`; вероятность модели на синтетике «Миранда» выше порога, на
  обычной речи — ниже (TFLite Micro собирается и на ноутбуке не нужен — модель
  проверяется на Mac через LiteRT по тем же признакам).
- Сборка прошивки `tools/build.sh` (arduino-cli здесь).
- Чек-лист на плате (README): «Миранда» срабатывает с 1–3 м, разговор/ТВ час —
  сколько ложных; эхо от своего ответа не будит колонку.

## Не-цели

- Своя «Кузя» (бэклог), загрузка модели по сети, несколько слов сразу.
- Перепроверка слова на Mac (двухступенчатая проверка — бэклог).
