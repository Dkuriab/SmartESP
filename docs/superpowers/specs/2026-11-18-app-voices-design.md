# Этап 2б: голоса, приложение и управление ядром

Статус: черновик, ждёт утверждения владельцем. Дополнение к
`2026-11-18-core-design.md` (разделы 6.6, 6.8, 6.9, 8 «этап 2», 9). Сеть моделей
(`delegate`, несколько исполнителей) — следующее дополнение, здесь её нет.

## 1. Зачем

- Голос Piper Irina владельцу не нравится. Нужен приятный спокойный женский голос.
  Прослушивание (`~/SmartEsp/voice-audition/`) оставило двух кандидатов:
  - Silero v5 (xenia, baya, kseniya);
  - Vosk TTS 0.9 (женские голоса).

  Владелец хочет оба, а выбирать на слух — в приложении.
- Сейчас ядро — окно терминала, настройки — `config.yaml`, а журнал читается
  глазами. Нужно приложение, в котором удобно смотреть, что происходит (кто
  спросил, что услышано, какие пометки, кто ответил, сколько заняло), и
  настраивать без правки файлов.
- Переключение голоса и модели в приложении — заодно проверка, что сменные
  части ядра действительно меняются без переделки кода и без перезапуска.

## 2. Цели, не-цели, анти-цели

**Цели**
- Три вида голоса: `piper`, `silero`, `vosk`. У каждого есть стиль `quiet`.
  Голос скачивается сам при первом выборе.
- В приложении можно смотреть:
  - схему «колонки → обработчики → диспетчер → голос»;
  - живую ленту ходов с подсветкой пути;
  - состояние ядра, Ollama и колонок.
- В приложении можно менять:
  - имена колонок;
  - модель и промпт диспетчера;
  - включение обработчиков;
  - голос (с кнопкой «Прослушать»).
- Изменения применяются на лету. Где нельзя — кнопка «Перезапустить ядро».
- Значок в строке меню виден всё время, пока работает ядро. Закрытое окно ядро
  не останавливает. «Выйти» честно останавливает ядро.
- Интерфейс открывается и с другого компьютера в домашней сети, по токену. Это
  основа для будущих клиентов (Android, iOS, Windows).

**Не-цели (этой версии)**
- Сеть моделей:
  - `delegate`;
  - больше одного исполнителя;
  - связи на схеме, которые тянутся мышкой.
- Люди, коннекторы, фоновые задачи, вкладка «Задачи».
- Склонение числительных: «до 5 часов» прочтётся «до пять часов».
- Подпись Apple Developer ID и нотаризация. Приложение собирается и
  подписывается локально (ad-hoc).
- Светлая тема.

**Анти-цели (провал, даже если «работает»)**
- Для того, что есть в приложении, всё ещё нужно править `config.yaml` руками.
- Переключение голоса или модели обрывает ответ, который звучит сейчас, или
  оставляет колонку без голоса.
- После «Выйти» ядро продолжает работать. Или после падения приложения ядро
  остаётся сиротой.
- Интерфейс ходит в ядро мимо `/api/v1`, через «скрытые» пути.
- Модули ядра знают про конкретный голос или конкретную модель. Всё работает
  через договоры и реестры (`core/CLAUDE.md`).

## 3. Ограничения

- **Mac:** macOS 15.3, Apple Silicon. Установлены только Command Line Tools,
  Xcode нет: Swift 6.1 и SwiftPM. Пакет `.app` собирается скриптом и
  подписывается ad-hoc.
- **Инструменты:** Node 25, npm 11.
- **Ядро:** правила `core/CLAUDE.md`:
  - модули не импортируют друг друга;
  - `main.py` — только связка;
  - файл ≤ 300 строк, функция ≤ 50 строк, сложность ≤ 10.
- **Зависимости фиксируются точно:**
  - `pyproject.toml` через `==`, плюс `uv.lock`;
  - `package-lock.json`;
  - `Package.resolved`.
- **Уже есть в `uv.lock`:** `torch` 2.15 (через mlx-whisper), `onnxruntime` 1.32
  (через piper), `scipy`.
- **Лицензия Silero** — CC BY-NC-SA: только некоммерческое использование. Для
  дома это подходит. Записать это в README рядом с голосами.
- **Задержка.** Первая фраза ответа не должна заметно замедлиться. Замеры
  синтеза фразы:
  - Piper: 0,07 с;
  - Silero: 0,04 с;
  - Vosk 0.9: 0,5–0,8 с, на грани.

## 4. Подходы (выбраны в разговоре)

| Вопрос | Выбрано | Отвергнуто и почему |
|---|---|---|
| Как живёт ядро | **Дочерний процесс приложения.** Окно закрыто — ядро работает, виден значок. «Выйти» — ядро честно останавливается. Приложение упало — ядро завершается само. | Служба launchd (её рекомендовал исполнитель в разговоре): живёт отдельно от приложения, и «Выйти» её не останавливает — против условия владельца «закрываю — всё заканчивается». Ядро внутри Swift-процесса (встроенный Python) — сложно и хрупко. |
| Как применяются изменения | **На лету.** Новое собирается в фоне, затем подменяется. Ответ, который звучит сейчас, договаривается по-старому. Перезапуск — только для порта и распознавания. | Перезапуск на любое изменение: проще, но каждый раз 20–40 с тишины на прогрев, и подбирать голос на слух неудобно. |
| Где голоса | **В процессе ядра.** Реализации договора `TextToSpeech` в реестре `TTS_KINDS`. | Отдельный процесс TTS: незачем, синтез быстрый, `torch` уже есть. |
| Интерфейс | **Веб:** React + Vite + React Flow. Страницу раздаёт ядро. Mac-обёртка — Swift, WKWebView и значок в строке меню. Решено в основном дизайне. | Нативный SwiftUI: не открыть из сети и не переиспользовать для других клиентов. |

## 5. Как устроено

### 5.1 Голоса (`core/smartesp/tts/`)

- **Реестр `TTS_KINDS` в `main.py`:** `piper`, `silero`, `vosk`. Каждая реализация
  — свой файл.
- **Настройки:** `tts.kind` и `tts.voice`. По умолчанию — `silero` / `xenia`.
  У старых установок без своих изменений голос сменится сам: в `config.yaml`
  хранятся только изменения владельца.
- **Каталог голосов.** Каждая реализация отдаёт список своих голосов: вид,
  голос, подпись для человека, размер скачивания. API показывает каталог с
  признаком «скачан».
  - `piper`: `ru_RU-irina-medium`, плюс любые `.onnx`, которые уже лежат в
    `voices/`.
  - `silero`: `xenia`, `baya`, `kseniya`. Модель `v5_ru`, синтез на 24 кГц.
  - `vosk`: женские голоса модели `vosk-model-tts-ru-0.9-multi`.
- **Скачивание.** Голос скачивается сам в `<data>/voices/<вид>/…`. У Piper
  остаётся прежний путь `voices/<голос>.onnx`, он совместим с тем, что уже
  скачано.
  - Файл качается во временный и переименовывается, только когда скачан
    целиком.
  - Ход скачивания уходит в ленту событий.
  - Ошибка скачивания попадает в состояние, а голос остаётся прежним.
  - `tools/download_voice.sh` больше не нужен: удалить и убрать из README.
- **Источники (проверить при реализации):**
  - Piper — Hugging Face `rhasspy/piper-voices`, как сейчас;
  - Silero — `https://models.silero.ai/models/tts/ru/v5_ru.pt`, загрузка через
    `torch.package`, без `torch.hub` и без GitHub во время работы;
  - Vosk — `https://alphacephei.com/vosk/models/vosk-model-tts-ru-0.9-multi.zip`,
    пакет `vosk-tts`.
- **Голос не скачан при старте.** Ядро скачивает его в фоне и при этом уже
  принимает колонки и запросы API (см. 5.4, «Старт»).
  - Пока голос не готов, отвечает любой уже скачанный голос (у старых
    установок — Ирина).
  - Скачанных голосов нет совсем — колонка получает сигнал ошибки, а
    скачивание повторяется через 30 с, 2 мин, 5 мин и так далее.
  - Состояние и ошибка видны в `status` и в интерфейсе.

  Так Mac без интернета со старой установкой не перестаёт отвечать из-за
  того, что сменился голос по умолчанию.
- **Числа словами** для Silero и Vosk. Общий помощник в `tts/`
  (`num2words`, `lang="ru"`): «в 8 утра» → «в восемь утра»; дроби и отрицательные
  числа тоже. Piper читает цифры сам и помощник не использует.
- **Неподдерживаемые символы.** Silero молча выкидывает латиницу и редкие
  символы, а Vosk на незнакомом символе падает. Реализация чистит текст до
  синтеза. Если предложение всё равно не синтезируется — запись в журнал и
  следующее предложение, ответ не обрывается.
- **Стиль `quiet`** у всех трёх: громкость отсчётов ×0,35 и чуть медленнее.
  - Piper — `length_scale` 1,15, как сейчас.
  - Vosk — скорость речи модели.
  - Silero — SSML `prosody rate`, если работает. Если нет — только громкость.
- **Синтез.** В потоке (`asyncio.to_thread`), выход ресемплируется в 16 кГц
  существующим `tts/resample.py`. Silero работает на CPU: 0,04 с хватает, MPS
  не нужен.

### 5.2 Применение настроек на лету (новый модуль `smartesp/control/`)

- **«Пульт»** хранит текущие настройки и применяет изменения. Реализации он
  получает от `main.py` функциями-сборщиками (через реестры) и не импортирует
  другие модули.
- **Подмена частей:**
  - Оркестратор получает методы подмены голоса, исполнителя и обработчиков.
    Каждый ход берёт ссылки на части в начале, поэтому звучащий ответ
    договаривается старыми частями.
  - Хаб колонок получает подмену имён.
  - История — подмену пределов.
- **Порядок изменения:**
  1. проверить новые настройки;
  2. собрать новые части в фоне (скачать, загрузить, прогреть);
  3. подменить части;
  4. записать `config.yaml` (только изменения владельца, через `config/loader`);
  5. отправить событие «применено».

  Сбой на любом шаге — старое остаётся, `config.yaml` не трогается, в событии
  пишется ошибка.
- **На лету меняются:**
  - имена колонок;
  - `tts`;
  - модель, промпт и `keep_alive` входного исполнителя;
  - `stages`;
  - `history`.

  **Требуют перезапуска:** `server`, `stt`, `arbitration`. Такие изменения
  записываются, а ответ API говорит «нужен перезапуск».
- **Смена модели диспетчера.** Новую модель надо прогреть, на это есть 120 с.
  Не прогрелась (например, не влезла в память) — остаётся старая. После
  подмены старая модель выгружается из Ollama (`keep_alive=0`).
- **Очередь.** Изменения применяются по одному. Следующее ждёт, пока закончится
  предыдущее.

### 5.3 События (новый договор и модуль `smartesp/events/`)

- **Договор `EventSink`** (`publish(event)`) — в `contracts`.
  - Оркестратор публикует шаги хода:
    - начало;
    - распознанный текст;
    - пометки;
    - исполнитель;
    - первый текст;
    - первый звук;
    - стиль;
    - конец с итогом и задержками.
  - Хаб публикует:
    - подключение и отключение колонок;
    - `wake`;
    - итог арбитража.
  - Пульт публикует применение настроек, ход скачивания и состояние ядра.
- **Реализация** рассылает события подписчикам WebSocket и хранит последние
  100 ходов в памяти. Ходы не сохраняются на диск, долгая память — журнал.

### 5.4 API (новый модуль `smartesp/api/`)

- **Адрес:** `/api/v1/…` на том же сервере, что и `/device`. Схема OpenAPI
  генерируется сама.
- **Токен** создаётся при первом старте в `<data>/token` (случайная строка).
  - HTTP: заголовок `Authorization: Bearer`.
  - WebSocket: `?token=`.
  - Токен нужен и с `127.0.0.1`. `/device` по-прежнему без токена.
- **Ресурсы (имена — на усмотрение исполнителя):**
  - `GET status` — версия, время работы, состояние ядра (`warming`, `ready`,
    `stopping`), Ollama (доступна, какая модель загружена), колонки (id, имя,
    в сети, IP, версия прошивки, когда была видна), идёт ли применение или
    скачивание.
  - `GET config` — действующие настройки и какие ключи изменены владельцем.
  - `PATCH config` — частичное изменение в форме `config.yaml`. Отвечает
    сразу, не дожидаясь применения (см. ниже «Изменения»).
  - `GET models` — модели Ollama с размером.
  - `GET voices` — каталог голосов.
  - `POST voices/download` — скачать голос.
  - `POST voices/preview` — фраза-образец (вид, голос, стиль, свой текст)
    → `audio/wav`. Голос должен быть скачан.
  - `GET turns` — последние ходы из памяти.
  - `POST restart`.
  - `WS events`.
- **Перезапуск.** Ядро честно останавливается (5.6) и запускает само себя
  заново в том же процессе (`os.execv`). Так перезапуск работает и из
  приложения, и из терминала, а приложение не теряет процесс.
- **Раздача интерфейса.** Ядро отдаёт собранный `ui/dist` на `/`. Если
  интерфейс не собран — страница с командой сборки.
- **Старт.** Сервер (`/api/v1`, `/device`, интерфейс) поднимается сразу, до
  прогрева. Прогрев и скачивания идут в фоне, их ход виден в `status` и в
  событиях. Колонки подключаются сразу, но на `wake`, пока ядро в состоянии
  `warming`, получают сигнал ошибки.
- **Файл запуска.** Сразу после подъёма сервера ядро пишет
  `<data>/run/core.json` (порт, pid) и удаляет его при остановке. По этому
  файлу приложение узнаёт порт, а дальше следит за `status`.
- **Изменения — без долгих запросов.** Применение может идти минуты
  (скачивание Vosk, прогрев модели до 120 с), поэтому запрос его не ждёт.
  `PATCH config` проверяет настройки и сразу отвечает одним из трёх:
  - «принято» с номером изменения;
  - «нужен перезапуск»;
  - ошибка проверки.

  Итог применения (применено или откат с ошибкой) приходит событием с тем же
  номером и виден в `status`. `POST voices/download` устроен так же.

### 5.5 Интерфейс (`ui/`, свой `CLAUDE.md`)

- **Технологии:** TypeScript, React, Vite, `@xyflow/react`.
- **Клиент API** генерируется из OpenAPI (`openapi-typescript`) и лежит в git.
  Скрипт обновления — в `package.json`.
- **Вид** — по утверждённому наброску `2026-11-18-app-mockup.html` (копия
  макета из разговора): тёмный холст в точку и плавающие скруглённые панели.
  Тема только тёмная, все тексты по-русски.
- **Слева — списки:** колонки (имя, точка «в сети»), обработчики (вкл/выкл),
  диспетчер, голос.
- **В центре — схема** «колонки → обработчики → диспетчер → голос». Раскладка
  автоматическая. Колонка не в сети — пунктир. Путь последнего хода
  подсвечен.
- **Справа — настройки выбранного блока:**
  - колонка: имя (правится), MAC, IP, прошивка, в сети ли;
  - обработчик: вкл/выкл, описание;
  - диспетчер:
    - модель — список из `GET models`, с размером;
    - промпт — правится;
    - итоговый промпт с правилами обработчиков — только для чтения;
  - голос:
    - каталог по видам, у каждого голоса размер и «скачан»;
    - кнопки «Скачать», «Прослушать» (обычный и тихий) и «Выбрать»;
    - ход скачивания.
- **Снизу — лента ходов вживую:** время, колонка, вопрос, пометки, ответ,
  стиль, задержки. Клик по ходу подсвечивает его путь на схеме.
- **Сверху:** вкладки «Схема» и «Лента», справа — состояние ядра, Ollama и
  колонок (N из M в сети).
- **Плашка «Нужен перезапуск»** с кнопкой — когда изменение требует перезапуска.
- **Токен.** Берётся из `?token=` при открытии, запоминается в `localStorage`
  и убирается из адреса. Для входа с другого компьютера в настройках
  показывается адрес с токеном — его можно скопировать.
- **Обрыв связи.** WebSocket событий переподключается сам. После
  переподключения интерфейс заново запрашивает состояние и ходы.

### 5.6 Честная остановка ядра

**Когда:** по SIGTERM, SIGINT или по смерти родителя. Ядро, запущенное с
`--parent-watch`, следит за закрытием stdin.

**Шаги:**
1. Состояние становится `stopping`, уходит событие. Новые `wake` не
   принимаются.
2. Звучащим ответам даётся договорить до 10 с. После этого — `cancel_turn`
   колонкам.
3. Соединения с колонками закрываются. Колонки сами переподключатся к
   следующему запуску.
4. Модель диспетчера выгружается из Ollama (`keep_alive=0`). Если Ollama не
   отвечает за 1 с, шаг пропускается.
5. Удаляется `run/core.json`, журнал сбрасывается на диск, код выхода 0.

Вся остановка — не дольше 15 с.

### 5.7 Mac-приложение (`app/`, свой `CLAUDE.md`)

- **Сборка.** Пакет SwiftPM: AppKit и WKWebView. Скрипт `app/build.sh` собирает
  `app/build/SmartEsp.app`:
  - пишет `Info.plist`;
  - зашивает путь к репозиторию;
  - подписывает ad-hoc.

  С флагом `--install` копирует приложение в `/Applications`.
- **Запуск ядра.** Приложение запускает
  `uv run --project <repo>/core python -m smartesp --parent-watch` дочерним
  процессом, с той же `SMARTESP_HOME`, если она задана.
  - `uv` ищется в `~/.local/bin` и `/opt/homebrew/bin`: при автозапуске PATH
    короткий.
  - Ядро уже запущено не приложением (найден живой `run/core.json` и порт
    отвечает) — приложение подключается к нему, но при «Выйти» его не
    останавливает и пишет об этом в меню.
- **Значок в строке меню** (символ SF) показывает состояние ядра:
  - запускается;
  - работает;
  - ошибка или остановлено.
- **Меню:**
  - строка состояния («Ядро работает · колонок 2 · Ollama ✓»);
  - «Открыть SmartESP»;
  - «Перезапустить ядро»;
  - «Журнал» — открывает `logs/core.log` в «Консоли»;
  - «Запускать при входе» — `SMAppService.mainApp`. Если с ad-hoc подписью не
    работает — LaunchAgent, который открывает приложение;
  - «Выйти».
- **Окно** — WKWebView с `http://127.0.0.1:<порт>/?token=…`. Токен приложение
  читает из `<data>/token`. Пока ядро прогревается, показывается заглушка
  «Ядро запускается…».
  - Закрыть окно → приложение остаётся в строке меню, значок в Dock прячется.
  - Cmd+Q и «Выйти» → полный выход.
- **Выход.** Меню показывает «Останавливаю ядро…», затем:
  1. SIGTERM ядру;
  2. ждать до 15 с;
  3. SIGKILL;
  4. выход.
- **Ядро упало само.** Значок «ошибка». Приложение перезапускает ядро не чаще
  3 раз в минуту, дальше ждёт кнопки «Перезапустить».

## 6. Проверка

**Ядро (тесты на подделках)**
- Числа словами.
- Каталог и скачивание голосов с поддельным HTTP: успех, обрыв, атомарность.
- Подмена на лету:
  - звучащий ход договаривает старым голосом, следующий — новым;
  - сбой прогрева — откат, а `config.yaml` не тронут.
- API с токеном и без: 401.
- События поддельного хода.
- Честная остановка: звучащий ход договаривает, новый `wake` отклоняется,
  выход в срок.
- Смерть родителя: stdin закрыт → ядро выходит.

**Ядро (тесты с моделями, `@pytest.mark.models`)**
- Каждый голос синтезирует фразу с числами.
- `quiet` тише `normal`.

**Интерфейс**
- Проверка типов.
- Тесты разбора событий и состояния (vitest).
- Сборка.

**Приложение**
- `swift build`.
- Чек-лист руками:
  1. Запуск → значок → окно.
  2. Закрыть окно → значок есть, колонка отвечает.
  3. «Выйти» → `pgrep -f smartesp` пусто, `ollama ps` без модели диспетчера.
  4. `kill -9` приложения → ядро выходит за 2 с.
  5. Сменить голос, пока звучит ответ → ответ договаривает старым, следующий
     звучит новым.
  6. «Прослушать» играет образец.
  7. Сменить модель и переименовать колонку.
  8. Браузер с другого компьютера: с токеном работает, без токена — 401.

## 7. Порядок работ (отдельные планы)

1. **Голоса** (ядро). Владелец сможет слушать новые голоса, пока делается
   остальное.
2. **Ядро для приложения:** события, пульт, API, токен, честная остановка,
   раздача интерфейса.
3. **Интерфейс.**
4. **Mac-приложение.**

## 8. Решения, принятые без обсуждения (проверить)

**Голоса**
- Голос по умолчанию — Silero xenia. Ирина остаётся в каталоге.
- Голоса скачиваются сами, скрипт `download_voice.sh` удаляется.
- Silero синтезирует на 24 кГц: выход всё равно 16 кГц.

**Ядро и API**
- Ядро — дочерний процесс приложения, а не служба launchd. Причина — условие
  «закрываю — всё заканчивается».
- При «Выйти» и при перезапуске модель диспетчера выгружается из Ollama, чтобы
  освободить память.
- Перезапуск ядра — `os.execv` того же процесса.
- Токен нужен и для локальных запросов.
- В ленте последние 100 ходов в памяти. После перезапуска ядра лента пуста,
  история остаётся в журнале.

**Приложение**
- «Запускать при входе» — переключатель в меню, по умолчанию включён.
- Приложение подключается к ядру, запущенному из терминала, но не
  останавливает его.

**Зависимости**
- `vosk-tts` 0.3.61 и `num2words` 0.5.14 встают на текущие версии без
  конфликтов (проверено `uv pip compile`).
- Если Silero через `torch.package` потребует ещё библиотеку — добавить её.
- Если конфликт неразрешим — этот голос откладывается, остальные идут
  дальше. Отдельный процесс TTS не делаем.
