# Обучение моделей («Обучение» в приложении) и слово «Кузя» — дизайн

Дата: 2026-11-22. Просьба владельца: обучить своё слово пробуждения; в приложении —
отдельная вкладка обучения, «скорее всего это не единственная модель, которую мы будем
обучать». Решения владельца: обучаем **«Кузя» и «Эй, Кузя»**, лучшее выбираем по
замерам; живые записи — **через колонку** (тот же микрофон и шумоподавление, что у слова
пробуждения).

## Цели и не-цели

- Цель: владелец сам записывает голоса семьи, запускает обучение и видит итог (сколько
  слов пропущено, сколько ложных срабатываний в час) — без терминала.
- Цель: новая обучаемая модель = новая папка «набора для обучения»; ядро и приложение не
  меняются (как коннекторы).
- Не-цели (потом): загрузка модели на колонку по сети (пока — прошивка по USB),
  перепроверка слова на Mac (двухступенчатая), запись срабатываний «было/не было» с колонок.

## Подходы

1. **Набор для обучения — отдельная программа со своим описанием, ядро её запускает**
   (выбрано). Тяжёлое (TensorFlow, гигабайты данных) — не в ядре; ядро хранит данные,
   записывает с колонки, запускает шаги, передаёт ход в приложение.
2. Обучение в ядре: TensorFlow и датасеты в зависимостях ядра, а ядро про «Кузю» знает —
   против правила «в ядре нет кода возможностей».
3. Только скрипты в терминале: быстро, но владелец просил вкладку и не одну модель.

## Как устроено

### Набор для обучения: `trainers/<id>/`

- Свой uv-проект (как `connectors/<id>/`), описание `trainers/<id>/smartesp.json`:
  `id`, `title`, `targets` — что обучаем, по умолчанию; `steps` — шаги
  (`[{id, title, command, args}]`, подстановки `{repo}`, `{data}`, `{target}`).
- **Цель** (отдельная модель) — `{id, title, positive: [фразы], negative: [фразы]}`:
  «Откликаться на» и «Не откликаться на». Владелец правит списки во вкладке и добавляет
  свои цели (решение владельца 2026-11-22: например «Кузьма» в той же модели). Цели
  хранятся в `~/SmartEsp/training/<набор>/targets.json`, начальные — из описания набора:
  - `kuzya` «Кузя»: откликаться на «Кузя», «Кузьма»;
  - `hey_kuzya` «Эй, Кузя»: откликаться на «Эй, Кузя».
  Модель «Кузя» сработает и на «Эй, Кузя» (слово внутри) — сравниваем удобство против
  ложных срабатываний. Короткие варианты («Кузь») — отдельной целью и по замерам.
- Записи — по фразам: `data/<цель>/<positive|negative>/<фраза>/<человек>/<n>.wav`;
  при записи приложение подсказывает, какую фразу сказать.
- Шаг пишет ход работы строками JSON в stdout: `{"stage": "…", "done": n, "total": m}`,
  итог — `{"result": {…}}`; остальное — журнал.

### Ядро: модуль `training/` (общий, без знания о словах)

- Данные — `~/SmartEsp/training/<набор>/data/…/<n>.wav` (16 кГц, моно), итоги — `…/runs/<время>/` (модель, манифест, `result.json`).
- **Запись с колонки:** `listen` колонке ходом ядра → реплика не идёт в разговор (без
  распознавания и ответа), её звук сохраняется в датасет. Колонка пикает, слушает до
  паузы 0,5 с — прошивку не меняем. Ход в ленту не попадает.
- Шаги — подпроцессы по одному за раз, «Остановить»; события `training_*` (ход, конец,
  итог) в ленту событий интерфейса; журнал шага.
- API: наборы и их описание; датасеты (сколько записей у кого); записать с колонки;
  прослушать/удалить запись; запустить/остановить шаг; итоги прогонов.

### Набор `trainers/wakeword/` (microWakeWord)

- Python 3.12, TensorFlow 2.21 на CPU (на Apple Silicon GPU медленнее — так у авторов),
  microWakeWord из `OHF-Voice/micro-wake-word` на закреплённом коммите, `ai-edge-litert`,
  `pymicro-features`; версии — `==` и `uv.lock`.
- Шаги:
  1. **«Скачать данные»** (один раз, ~6,5 ГБ в `~/SmartEsp/training/cache`): готовые
     признаки отрицательных примеров `kahrendt/microwakeword` (речь, тишина, застолье и
     проверочное застолье для «ложных в час»), фоны (MIT RIR, FMA, AudioSet).
  2. **«Синтетика»** (на цель): фразы «Откликаться на» голосами Silero, Piper и Vosk
     (голоса из `~/SmartEsp/voices`), скорость и высота с разбросом, с «!» и «?»; фразы
     «Не откликаться на» (по умолчанию: Кузов, Кузнец, Гуся, Дуся, Муся, Вася, Ксюша, Куда,
     Пузо, Узя, …) — как отрицательные.
  3. **«Обучить»** (на цель): признаки с аугментацией (шум, эхо комнаты, сдвиг),
     mixednet с `stride 3` (вход [1, 3, 40], как в прошивке), живые записи с весом выше
     синтетики (5 против 2), похожие слова — отрицательные с повышенным штрафом.
     Итог: модель `.tflite`, манифест, кривая «порог → пропуски / ложные в час»;
     порог выбирается наименьшими пропусками при ≤ 0,5 ложных в час; проверка, что
     вход модели — [1, 3, 40].
  4. **«Встроить в прошивку»**: `tools/embed_model.py` → `ModelData.cpp` (порог и окно из
     итога), сборка `tools/build.sh`; прошивает владелец.
- Отложенные проверкой: 20 % живых записей каждого человека — только для проверки (модель
  их не видит), в итоге — «узнаёт ваши живые записи: N %».

### Вкладка «Обучение» в приложении

- Список наборов → набор: цели; датасеты (по людям: сколько записей; «Записать с
  колонки» — выбор колонки и человека, подсказка, что сказать; прослушать/удалить
  последнюю); шаги с ходом, журналом и «Остановить»; итоги прогонов (пропуски, ложные в
  час, порог) с пометкой лучшего; «Встроить в прошивку».

## Сколько записей

На человека: ~50 на главную фразу каждой цели и ~30 на каждую дополнительную («Кузьма»),
с разных мест комнаты (0,5–3 м), разной громкостью и интонацией; ~20 «Не откликаться на». Синтетики — десятки тысяч (генерируется сама).

## Порядок

1. Запись с колонки + данные + вкладка с записью — владелец начинает записывать.
2. Набор `wakeword`: скачать данные, синтетика, обучение (проверка на этом Mac).
3. Шаги из приложения: ход, журнал, итоги прогонов, встраивание.
4. Обучить обе цели, сравнить, прошить лучшую.

Потом — «Клиенты» (бот Telegram в приложении и источник хода на схеме, дизайн одобрен).
