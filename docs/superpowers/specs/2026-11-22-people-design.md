# Люди: кто говорит (этап 4, v1)

Дата: 2026-11-22. Дополнение к дизайну ядра (`2026-11-18-core-design.md`, этап 4
«Люди»: `people`, обработчик «кто говорит», `_meta.person`). Связанный пункт
бэклога — «Незнакомый голос → предложить добавить человека» (в v1 не входит).

## 1. Зачем

Кузя должен понимать, **кто** из домашних говорит, по голосу каждой фразы. Тогда
ответы, заметки, таймеры и лента становятся личными: таймер Ани — у Ани, заметка
Дани — в его папке, в ленте видно «Кухня · Аня».

Сейчас человек известен только у хода через API (Telegram: `person` в вопросе),
а до инструментов коннекторов он не доходит вовсе: сеть исполнителей вызывает
инструменты с `person=None`.

**Голос не пароль** (анти-цель основного дизайна): узнавание — удобство, а не
доступ. Ошибка узнавания не должна открывать ничего опасного.

## 2. Что входит в v1

1. Узнавание голоса на Mac, в ядре, по звуку фразы (PCM 16 кГц моно).
2. Модуль `core/smartesp/people/`: реестр людей в `<data>/people/`, запись
   образцов голоса с колонки, узнавание.
3. Узнанный человек — в ходе (`Turn.person`), в ленте, в справке модели
   «говорит — Аня» и в `_meta` каждого вызова инструмента (`person` — постоянный id, `person_name` — имя).
4. Вкладка «Люди» в приложении: добавить человека, записать 5–10 фраз с колонки,
   сколько образцов, переименовать/удалить, последние узнавания.

Не входит (следующие шаги, §9): знакомство с незнакомым голосом, дообучение по
ходу разговора, запись образцов через микрофон браузера, права по людям.

## 3. Подходы

| Подход | Плюсы | Минусы |
|---|---|---|
| **A. Голосовые отпечатки (эмбеддинги) + косинусное сходство** | Маленькая готовая модель, ~15 мс на фразу; новый человек — без обучения, 5 фраз; открытое множество («не узнан») — порогом | Нужен порог; качество зависит от микрофона колонки |
| B. Классификатор, дообучаемый на голосах семьи | Может быть точнее на своих | Нужно обучение при каждом новом человеке, много записей, «не узнан» — плохо |
| C. Облачный сервис узнавания | Ничего не держим локально | Голос уходит из дома — против приватности; задержка сети |
| D. Узнавание на колонке (ESP32-S3) | Нет звука в сети | Памяти и процессора не хватит на модель, все равно нужен реестр на Mac |

Выбран **A**: стандартный путь для «кто из нескольких известных», работает
офлайн, добавление человека — запись нескольких фраз без обучения.

## 4. Модель

### 4.1 Кандидаты

Все — ONNX-модели голосовых отпечатков из релиза `speaker-recongition-models`
проекта sherpa-onnx (k2-fsa; имя тега — с опечаткой в оригинале). Вход у всех —
80 логарифмов мел-фильтров (Kaldi fbank, 25/10 мс) с вычтенным средним. Fbank
считаем сами на numpy (`people/features.py`): сверено с kaldi-native-fbank,
расхождение < 2·10⁻⁴. Новых библиотек не нужно: `onnxruntime` уже в окружении
ядра (через piper-tts), `numpy` — тоже.

### 4.2 Замер

Mac Studio (Apple M2 Ultra), onnxruntime 1.32 на процессоре. 9 синтетических
голосов ядра (Piper: Ирина, Денис, Дмитрий, Руслан; Silero: xenia, baya,
kseniya, aidar, eugene), по 16 бытовых фраз 1,2–3,6 с (средняя ~2,2 с).
Записаны первые 5 фраз (средний отпечаток), проверяются остальные 11 (99 проверок).
«Колонка» — грубое подобие записи с колонки: тише в 2–5 раз, эхо 30 мс, завал
верхов, шум с SNR 15 дБ.

| Модель | Размер | мс/фраза (4 потока / 1 поток) | Чисто: top-1, EER | Колонка (запись и проверка): top-1, EER | Чистая запись, проверка «колонкой»: EER |
|---|---|---|---|---|---|
| **3D-Speaker CAM++ zh-en advanced** | 28 МБ | **15 / 35** | 100 %, 0 % | 100 %, 0 % | 0 % |
| WeSpeaker CAM++ LM (VoxCeleb) | 29 МБ | 15 / 34 | 100 %, 0 % | 100 %, 0,1 % | 3 % |
| WeSpeaker ResNet34 LM (VoxCeleb) | 27 МБ | 35 / 117 | 100 %, 0 % | 100 %, 0,3 % | 0,3 % |
| 3D-Speaker ERes2Net (VoxCeleb) | 26 МБ | 56 / 107 | 100 %, 0 % | 100 %, 1 % | 1 % |

Открытое множество (говорит тот, кого не записывали; CAM++ zh-en, условие
«колонка», 5 фраз записи):

| Порог, отрыв от второго | Свой узнан | Чужой принят за своего |
|---|---|---|
| 0,45 | 100 % | 24 % |
| 0,50 | 100 % | 12 % |
| 0,55 | 100 % | 2 % |
| **0,55, отрыв 0,05** | **100 %** | **1 %** |
| 0,60 | 100 % | 0 % |

### 4.3 Выбор

**3D-Speaker CAM++ `speech_campplus_sv_zh_en_16k-common_advanced`** (файл
`3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`, sha256
`53cab20b…4574b`, 192 числа на отпечаток):
- самая быстрая из точных: ~15 мс на фразу — меньше 5 % времени распознавания
  речи, ход не задерживается;
- обучена на ~200 тыс. голосов на двух языках — устойчивее к «не английскому»,
  чем модели только на VoxCeleb; на синтетических русских голосах — лучший
  разрыв своих и чужих при смене условий записи;
- лицензия Apache-2.0 (3D-Speaker).

Порог по умолчанию — **0,55** и отрыв от второго по сходству человека **0,05**
(иначе «не узнан»). Это константы `people/matching.py`; синтетические голоса
стабильнее живых, поэтому порог — первое, что проверить на настоящих колонках
(в «Последних узнаваниях» видны сходства).

Скачивание — один раз, как голоса TTS: по кнопке во вкладке «Люди», в
`<data>/models/speaker/`, через `.part` и проверку sha256 (версия закреплена
адресом релиза и хешем). Дальше — полностью офлайн.

## 5. Как устроено

### 5.1 Модуль `people`

```
people/
  features.py   — Kaldi fbank на numpy
  encoder.py    — ONNX-модель: PCM → отпечаток (договор VoicePrint), ленивая загрузка
  model.py      — какая модель, путь, скачивание с проверкой sha256
  matching.py   — средний отпечаток человека, лучший по косинусу, порог и отрыв
  store.py      — реестр людей: <data>/people/<id>/person.json, атомарная запись
  service.py    — People (договор PeoplePort): люди, образцы, узнавание, журнал
```

Тяжёлое (fbank + модель) — в пуле потоков (`asyncio.to_thread`), загрузка
модели — один раз под замком. Фраза короче 1 с не судится (отпечаток ненадёжен).

### 5.2 Договоры (`contracts/people.py`)

- `Person`, `VoiceSample`, `Recognition`, `SpeakerModelState` — dataclass'ы.
- `VoicePrint` — сменная часть: `model` (id модели), `embed(pcm) -> list[float]`.
  Отпечатки разных моделей несравнимы: у образца хранится id модели.
- `PeoplePort` — для API: люди, образцы, узнавания, модель.
- `Annotation.person`, `Annotation.person_id` — новые поля пометки: «обработчик узнал человека» (имя и постоянный id).

### 5.3 Ход

1. Обработчик `people` (`stages/people.py`, вид `people` в `STAGE_KINDS`)
   получает фразу вместе с остальными, параллельно, со своим таймаутом
   (`timeout_ms`, 300 мс по умолчанию — с запасом в 10–20 раз). Не уложился —
   пропущен, ход идёт без человека. Источник узнавания задаёт связка
   (`PEOPLE_VOICES.use(people.recognize)`), как у обработчика «система».
2. Узнан — справочная пометка «говорит — Аня» (`reference`, `person="Аня"`).
   Не узнан при записанных людях — пометка «голос не узнан» только для ленты
   (`to_model=False`). Никого не записано или модели нет — ничего.
3. `conversation.steps.understand` берёт человека хода из пометок
   (`turn.person`), если его ещё нет (у хода через API человек известен каналу —
   он главнее; голосовые сообщения через API обработчик не судит).
4. Лента: `turn_finished.person` уже есть, интерфейс показывает «Кухня · Аня».
5. Инструменты: ход ставит `CALL_CONTEXT` (`contracts/tools.py`) —
   `CallContext(person_id, device_id, person_name)`, хаб кладёт его в `_meta`
   каждого вызова. Сеть исполнителей не меняется.

**Решение владельца (2026-11-22): постоянный id, а не имя.** В `_meta.person` —
постоянный id человека (папка `<data>/people/<id>/`), в `_meta.person_name` — имя.
Скиллы раскладывают данные по id: переименование ничего у них не меняет. В ленте
(`Turn.person`, `TurnOut.person`) — имя, рядом `person_id`.

### 5.3а Связи с аккаунтами каналов

У человека — `links: [{channel, account}]` (`channel` — как `source` хода через API,
`account` — id в канале: `user_id` Telegram строкой). Связей у человека может быть
несколько, аккаунт — только у одного человека. `POST /api/v1/ask` и `/ask/voice`
принимают `account`; связка пропускает вопрос через `People.identify`: связан —
id и имя человека, не связан — id `"<source>:<account>"` и имя от клиента, без
`account` — без id. Бот (`clients/telegram`) шлёт `account=str(user_id)` всегда.
Во вкладке «Люди» — блок «Связи»: пользователи бота из его настройки
`TELEGRAM_USERS` или канал и аккаунт вручную.

Данные скиллов, записанные раньше по имени (папки «Аня» / «аня»), после перехода
на id не видны: скилл ищет папку id. Перенос — дело самих скиллов (в ядре нет
кода про их данные), см. отчёт ветки `feature/people-links`.

### 5.4 Запись образцов

`POST /api/v1/people/{id}/samples {device_id}` — тот же механизм, что у
«Обучения»: связка передаёт `DeviceHub.record` и «колонка свободна и умеет
слушать». Колонка пикает и слушает до паузы; из звука — отпечаток и сразу в
реестр. Звук **не хранится**.

### 5.5 Хранение и приватность

```
<data>/people/<id>/person.json   {id, name, created_at, samples: [{id, at, device_id, seconds,
                                   peak_db, model, embedding[192]}]}
<data>/models/speaker/<модель>.onnx
```

- Сырые записи не храним: голос с содержанием фраз — чувствительнее отпечатка,
  а для узнавания хватает отпечатков. Цена — при смене модели образцы надо
  перезаписать (5 фраз ≈ минута); образцы другой модели видны как «устаревшие»
  и в узнавании не участвуют.
- Файл человека — права 0600; удаление человека удаляет его папку целиком.
- Журнал узнаваний (последние 20: когда, колонка, кто, сходство, мс) — только в
  памяти, до перезапуска.

## 6. API

| Метод и путь | Что |
|---|---|
| `GET /people` | люди с образцами (без отпечатков) |
| `POST /people {name}` | добавить; имя 1–40 символов, уникальное |
| `PATCH /people/{id} {name}` | переименовать |
| `DELETE /people/{id}` | удалить с образцами |
| `POST /people/{id}/samples {device_id}` | записать образец с колонки |
| `DELETE /people/{id}/samples/{sample}` | удалить образец |
| `GET /people/recognitions` | последние узнавания |
| `GET /people/model` · `POST /people/model` | состояние модели · начать скачивание |

Ошибки: нет человека/образца — 404; колонка не может, модель не скачана — 409;
речи не было, неверное имя — 422.

## 7. Интерфейс

Новая вкладка верхней панели **«Люди»** (не внутри «Обучения»: там — обучение
моделей по наборам, а люди — самостоятельное понятие, которое дальше
понадобится в правах, привычках и ленте). Слева — список людей и «Добавить»,
справа — выбранный человек: имя (переименовать, удалить), образцы (сколько,
длительность, громкость, удалить), запись с колонки с подсказкой фразы
«Скажи: …» (по одной или «подряд»), внизу — «Последние узнавания». Модель не
скачана — сверху плашка «Скачать модель узнавания (28 МБ)».

## 8. Проверка

- Тесты без модели: поддельный `VoicePrint` (отпечаток зашит в PCM), реестр,
  сопоставление, обработчик, API, человек хода → `_meta.person`.
- Тест с настоящей моделью (`@pytest.mark.models`): два синтетических голоса
  различаются.
- На колонках (нет в этой среде): записать двух людей по 5 фраз, проверить
  «Последние узнавания» и порог.

## 9. Дальше

- **Незнакомый голос** (бэклог): «Я тебя не узнаю. Добавить нового человека?» —
  сценарий ядра из нескольких шагов, не чаще раза в N минут на колонку.
- Дообучение по ходу: уверенно узнанные фразы добавлять в образцы (с пределом).
- Запуск отпечатка параллельно с распознаванием речи (сейчас — после него, но
  ~15 мс на фоне сотен мс распознавания не заметны).
- Порог и отрыв — в настройках, если на живых голосах константы не подойдут.
- Запись образца через микрофон браузера (нужен https/разрешение в приложении).
