# Калории и Telegram — дизайн

Дата: 2026-11-19. Решения владельца в разговоре; помеченное «(моё)» — можно
поправить.

## 1. Зачем и принцип

Владелец хочет записывать съеденное и калории: дома голосом, вне дома — с
телефона, продукты — по штрихкоду. Правило владельца: **в ядре и в нашем
приложении нет кода под конкретную функцию.** Поэтому:
- логика еды — MCP-коннектор `food`;
- телефон — отдельный клиент: Telegram-бот, говорящий с ядром через его общий API;
- ядро получает только общий механизм «ход текстом/голосом через API».

FatSecret не нужен: от него владельцу нужны только штрихкоды, их даёт Open Food
Facts (+ своя база).

## 2. Части

### 2.1 Коннектор `food` (`connectors/food/`)

Как остальные коннекторы (`docs/superpowers/specs/2026-11-19-mcp-hub-design.md`,
4.4): uv-проект, FastMCP, stdio, данные в `SMARTESP_CONNECTOR_DATA` по людям,
русские описания и ответы. Отличие — **ходит в сеть** (Open Food Facts).

Инструменты:
- `food_log(what: str, grams: float = 0, barcode: str = "", when: str = "")` —
  записать съеденное. Калории ищутся по порядку:
  1. своя база продуктов (по штрихкоду или названию);
  2. прошлые записи дневника с тем же названием («как вчера»);
  3. Open Food Facts по штрихкоду (`world.openfoodfacts.org/api/v2/product/<код>`,
     свой User-Agent, кэш ответа в своей базе);
  4. встроенная таблица частых продуктов на 100 г (≈150 позиций; источник — USDA
     FoodData Central, общественное достояние; русские названия);
  5. не нашлось — ответ «Не знаю калорийность «…». Скажи, сколько ккал на 100 г»;
     запись не делается.
  `grams` нет, а у продукта есть вес упаковки — берётся он; иначе — спросить.
  Ответ: «Записала: гречка, 150 г — 515 ккал. За сегодня 1340 ккал.»
- `product_add(name: str, kcal_100g: float, protein: float = 0, fat: float = 0,
  carbs: float = 0, barcode: str = "", pack_grams: float = 0)` — продукт в свою
  базу (когда штрихкод не нашёлся или своё блюдо).
- `food_today()`, `food_summary(days: int = 7)` — итоги: ккал, Б/Ж/У, по дням.
- `food_undo()` — убрать последнюю запись; `food_find(query)` — что ел.

Хранение: `products.json` (своя база), `diary/YYYY-MM.jsonl` (запись — строка),
атомарно. Сеть: таймаут 5 с, нет сети — честный ответ, шаги 1, 2, 4 работают.

### 2.2 Telegram-бот (`clients/telegram/`, новая папка клиентов)

Отдельная программа (uv-проект), не часть ядра и не часть приложения.
- Пишешь текст или голосовое → бот отправляет ядру `POST /api/v1/ask`
  (см. 2.3) → ответ текстом в чат.
- **Фото штрихкода** → бот распознаёт штрихкод на Mac (библиотека `zxing-cpp`) и
  отправляет ядру текст «штрихкод 4601234567890» вместе с подписью к фото
  («200 г»). Отдельное приложение-сканер не нужно для начала (моё): фото
  штрихкода в Telegram — уже сканер. Мини-приложение со сканером в камере
  и нативные приложения — позже, если фото окажется неудобным.
- **Доступ только своим:** список разрешённых `user_id` Telegram в настройках
  бота; чужим — молчание (моё).
- Токен бота и токен ядра — в файле секретов бота вне git (`secrets.example`
  в git), как правило проекта.
- Связь с Telegram — исходящие запросы (long polling), порты не открываются.
  Сообщения проходят через серверы Telegram — владелец согласен.
- Человек хода — по `user_id` → имя из настроек бота (до этапа «Люди»).
- Ответы Кузи по своей инициативе (таймер, задача готова) в Telegram — позже:
  нужен канал уведомлений ядра наружу.

### 2.3 Ядро: ход через API (общий механизм)

`POST /api/v1/ask` (токен как у остальных ресурсов): `{text, person?, source:
"telegram"}` → `{answer, turn_id}`; голос — `POST /api/v1/ask/voice` (OGG/Opus
или WAV) → распознавание тем же STT → дальше как текст. Ход идёт тем же путём,
что с колонки (обработчики, исполнители, инструменты, история), но без звука;
в ленте — источник «Telegram». Делается **после** текущих планов (трогает
`conversation/` и `api/`); бот пишется сразу по этому договору, тесты — с
поддельным ядром.
