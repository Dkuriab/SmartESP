# SmartESP для Mac

Меню-приложение для ядра SmartESP: само запускает Python-ядро, следит за ним
и показывает веб-интерфейс в окне. Живёт в строке меню; пока открыто окно,
есть и в Dock. При автозапуске (вход в систему) окно не открывается — только
значок в строке меню.

## Нужно заранее

- `uv` (`brew install uv`);
- Swift-тулчейн swift.org (https://www.swift.org/install/macos/, `.pkg` ставится
  в `~/Library/Developer/Toolchains`) или Xcode. Swift из Command Line Tools
  не умеет собирать пакеты на этой macOS (`Invalid manifest`);
- ядро и интерфейс собраны по корневому `README.md` («Установка на новом Mac»).

## Сборка и установка

```bash
cd app
./build.sh             # app/build/SmartEsp.app (подпись ad-hoc)
./build.sh --install   # то же, плюс копия в /Applications/SmartEsp.app
```

`--install` сам закрывает запущенное приложение. Путь к репозиторию вшит в
приложение при сборке; переопределить — переменной `SMARTESP_REPO`. Папка
данных — `~/SmartEsp` (или `SMARTESP_HOME`).

После установки откройте SmartEsp из «Программ».

## Первый запуск

Если репозиторий лежит в «Документах» (а также на «Рабочем столе» или в
«Загрузках»), macOS спросит доступ к папке. Нажмите **«Разрешить»**. Пока окно
запроса висит, в меню строка «Нужно разрешение на папку «Документы»», а в окне
заглушка с подсказкой. Ядро стартует сразу после разрешения.

Если ядро после запуска 20 с молчит (нет ни файла запуска, ни строк в журнале),
а репозиторий в защищённой папке, в меню появится «Ядро молчит — возможно, ждёт
доступа к папке…». Причин две: окно запроса доступа спряталось или `uv` ещё
ставит зависимости — откройте «Журнал».

Нажали «Не разрешать» — приложение покажет «Ошибка: нет доступа к папке» и пункт
«Открыть настройки доступа». Вручную: Системные настройки → Конфиденциальность
и безопасность → Файлы и папки → SmartEsp → включить нужную папку, затем
«Перезапустить ядро». Сборка подписана ad-hoc, поэтому после пересборки macOS
может спросить разрешение заново.

## Меню

Значок в строке меню:

| Значок | Состояние |
|---|---|
| `waveform.circle` (контур) | ядро запускается, прогревается или останавливается |
| `waveform.circle.fill` (заливка) | ядро работает |
| `exclamationmark.triangle.fill` | остановлено, ошибка или нужен доступ к папке |

Пункты:
- первая строка — состояние, например «Ядро работает · колонок 1 из 2 ·
  Ollama ✓»; при ошибке под ней подсказка;
- «Открыть настройки доступа» — только когда нужен доступ к папке;
- «Открыть SmartESP» — окно с веб-интерфейсом;
- пульт ядра — виден только подходящий пункт:
  - «Запустить ядро» — ядро остановлено или ошибка;
  - «Остановить ядро» — своё ядро работает или запускается; после остановки
    приложение само его не запускает;
  - «Взять управление» — ядро запущено не из приложения (см. «Ядро из терминала»);
- «Перезапустить ядро» (недоступен, пока ядро остановлено);
- «Журнал» — открывает `core.log` в Консоли;
- строка «Ollama: работает / не отвечает / запускаю…» и «Запустить Ollama», когда
  Ollama не отвечает (см. «Ollama»);
- «Запускать при входе» — автозапуск;
- «Выйти».

Пока ядро не работает, в окне вместо интерфейса заглушка: состояние, те же
кнопки пульта («Запустить ядро», «Остановить ядро», «Запустить Ollama») и строка
состояния Ollama.

## Ollama

Приложение раз в 5 с (и при открытии меню) спрашивает
`http://127.0.0.1:11434/api/version`. «Запустить Ollama» открывает
`Ollama.app` (`/Applications` или `~/Applications`), а если приложения нет —
запускает `ollama serve` в фоне (`/opt/homebrew/bin`, `/usr/local/bin` или
`PATH`) с выводом в `~/SmartEsp/logs/ollama.log`. Ollama, запущенная так,
остаётся работать и после выхода из SmartEsp. Не ответила за 30 с — в меню
ошибка; нет ни приложения, ни программы — «Ollama: не установлена».

## Закрыть окно или «Выйти»

Закрытие окна ядро не трогает: значок остаётся в строке меню, ядро работает,
значок Dock пропадает. «Выйти» останавливает ядро (до 15 с, потом принудительно)
и закрывает приложение. Если ядро упало, приложение перезапускает его (не
больше 3 раз за 60 с), дальше показывает ошибку до «Перезапустить ядро».

Второй запуск приложения не стартует второе ядро: показывает окно первого.
Если первое как раз выходит, второе дожидается его выхода (до 20 с) и
запускается само. Выход из системы и выключение во время «Выйти» не
отменяются: приложение дожидается остановки ядра и закрывается.

Ядро, которое вышло само с кодом 0 (его остановили сигналом или через API),
считается остановленным, а не упавшим: приложение его не перезапускает.

## Ядро из терминала

Если ядро уже запущено из терминала (`cd core && uv run python -m smartesp`),
приложение подключится к нему: в меню «Ядро запущено не из приложения». «Выйти»
такое ядро не останавливает, «Перезапустить ядро» перезапускает его через API.

«Взять управление» передаёт ядро приложению: приложение проверяет, что pid из
`~/SmartEsp/run/core.json` — это `python -m smartesp`, посылает ему SIGTERM,
ждёт выхода до 15 с и запускает своё ядро. Если ядро за 15 с не вышло, в меню
ошибка, а сам процесс не трогается (принудительно чужой процесс приложение не
убивает) — остановите его вручную и нажмите «Запустить ядро».

## Запускать при входе

Пункт включается сам при первом запуске, но только если приложение лежит в
`/Applications`: проверочные сборки не прописываются в автозапуск. Из других
мест пункт неактивен («только из «Программ»»); исключение — старая запись от
прежней сборки: её можно выключить.

Если пункт отмечен чертой и написано «ожидает разрешения», нажмите на него:
откроются Системные настройки → Основные → Объекты входа, там разрешите
SmartEsp. Если системный механизм не работает с ad-hoc подписью, используется
запасной LaunchAgent `~/Library/LaunchAgents/com.smartesp.app.plist`
(`open -a … --args --background`).

При автозапуске окно не открывается: приложение тихо стартует ядро, окно — по
«Открыть SmartESP». Отметку пункта меню приложение перечитывает при каждом
открытии меню, так что изменения в Системных настройках видны сразу.

## Мост для интерфейса

Страница ядра в окне приложения видит `window.smartespBridge === true` и может
попросить приложение открыть файлы:

```js
window.webkit.messageHandlers.smartesp.postMessage({ action: "openDataFolder" })
```

Действия: `openDataFolder` — папка данных в Finder; `openConfig` —
`config.yaml` в редакторе по умолчанию (нет такого — TextEdit); `revealLog` —
`core.log` в Finder. Другие действия, лишние поля и сообщения не со страницы
`http://127.0.0.1`/`localhost` приложение молча отбрасывает. Нет файла — открывается
его папка.

Окно показывает только ядро: переходы на `http(s)` по адресу и порту ядра
(`127.0.0.1`/`localhost`) грузятся в окне, другие `http(s)`-ссылки и `mailto`
открываются в браузере по умолчанию, остальное (`file://`, `blob:`, `data:` …)
отменяется — брошенный на окно файл не заменяет интерфейс. `<input type="file">`
(«Проиграть файл…») открывает обычное окно выбора файла.

## Журналы

- `~/SmartEsp/logs/core.log` — журнал ядра («Журнал» в меню);
- `~/SmartEsp/logs/core-stderr.log` — вывод `uv`/Python, если ядро упало до
  того, как начало писать свой журнал;
- `~/SmartEsp/logs/ollama.log` — вывод `ollama serve`, если Ollama запустило
  приложение.

## Если не работает

- **«Ошибка: Не найден uv»** — `brew install uv` (приложение ищет в
  `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin` и в `PATH`), затем
  «Перезапустить ядро».
- **«Порт 8765 занят другой программой»** — порт держит чужой процесс:
  `lsof -nP -iTCP:8765 -sTCP:LISTEN`; остановите его и нажмите «Перезапустить
  ядро».
- **«Ошибка: нет доступа к папке»** — см. «Первый запуск».
- **Окно с заглушкой «Ядро запускается…»** — ядро ещё не написало файл запуска
  или токен (`~/SmartEsp/run/core.json`, `~/SmartEsp/token`): первый старт
  долгий, `uv` ставит зависимости; смотрите «Журнал». Пока ядро прогревается
  (качаются модели), в окне уже интерфейс, а в меню «Ядро прогревается».
- **«Не задан путь к репозиторию»** — приложение собрано не через `build.sh`;
  пересоберите.

## Проверка руками

Порт 8765 свободен, файлы `~/SmartEsp` сохранены заранее.

1. `open app/build/SmartEsp.app`: значок появился, окно с заглушкой, потом
   интерфейс. `curl -s -H "Authorization: Bearer $(cat ~/SmartEsp/token)" 127.0.0.1:8765/api/v1/status`
   отвечает `ready`.
2. Закрыть окно: значок остался, `pgrep -f "python -m smartesp"` находит процесс.
3. `osascript -e 'quit app "SmartEsp"'`: за 15 с нет ни приложения, ни ядра,
   `~/SmartEsp/run/core.json` удалён.
4. Запустить снова, `kill -9 <pid приложения>`: ядро выходит за 3 с.
5. Запустить второй экземпляр: второго ядра нет.
6. Ядро из терминала, затем приложение: «Ядро запущено не из приложения»;
   «Выйти» — ядро из терминала живо.
7. Автозапуск: из `/Applications` пункт «Запускать при входе» работает
   (включить, выключить, при «ожидает разрешения» открываются Объекты входа);
   из `app/build` пункт неактивен.
8. Запрос «Документы»: репозиторий в `~/Documents`, права сброшены
   (`tccutil reset SystemPolicyDocumentsFolder`): приложение показывает «Нужно
   разрешение…», после «Разрешить» ядро стартует; после «Не разрешать» —
   «нет доступа к папке» и рабочий «Открыть настройки доступа».
9. Вход в систему: включить «Запускать при входе», выйти из системы и войти —
   значок есть, окно не открылось, ядро отвечает `status`.
10. Выход из системы и выключение при работающем ядре: macOS не пишет, что
    SmartEsp прервал выход; после входа `~/SmartEsp/run/core.json` нет или
    принадлежит новому ядру.
11. Сон и пробуждение с открытым окном: после пробуждения интерфейс на месте,
    без заглушки и перезагрузки страницы.
12. «Перезапустить ядро» с открытым окном: на время перезапуска заглушка или
    «Ядро прогревается», затем интерфейс сам загружается заново.
13. «Выйти» и сразу снова открыть SmartEsp: новое окно появляется после
    выхода прежнего экземпляра (до 20 с), второе ядро не запускается.
14. «Остановить ядро»: за 15 с ядра нет (`pgrep -f "python -m smartesp"`), в окне
    заглушка «Ядро остановлено» с кнопкой «Запустить ядро»; через минуту ядро
    всё ещё не запущено. «Запустить ядро» (в меню или в окне) — интерфейс снова в окне.
15. Ядро из терминала, затем приложение, «Взять управление»: в терминале ядро
    вышло само, в меню «Ядро работает», `pgrep -f "python -m smartesp"` —
    ровно один процесс, и он потомок SmartEsp (`ps -o ppid= -p <pid>`).
16. Остановить Ollama (выйти из Ollama.app): за 5 с в меню «Ollama: не отвечает»
    и «Запустить Ollama»; нажать — Ollama запускается, строка «Ollama: работает».
17. Мост: в окне Web Inspector недоступен, поэтому проверка — из вкладки «Ядро»
    (W7) кнопками «Папка данных», «config.yaml», «Журнал в Finder».
18. Колонка v3 на связи: «Проиграть файл…» открывает окно выбора файла поверх
    окна приложения, выбранный MP3/OGG играет на колонке, «Стоп» его гасит; «Отмена»
    в окне выбора — ничего не происходит.
19. Бросить аудиофайл из Finder на окно приложения: интерфейс остаётся на месте
    (файл не открывается в окне). На заглушке с «Остановить ядро» Return ядро не
    останавливает.
